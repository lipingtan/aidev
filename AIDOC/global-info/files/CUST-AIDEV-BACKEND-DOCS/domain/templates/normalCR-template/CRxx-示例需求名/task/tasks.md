## 并行任务分组说明

### 并行组 A（基础设施层）

**包含任务**：Task-001

**说明**：数据库表结构是所有业务逻辑的基础，必须最先执行。本组只有一个任务，执行完成后才能解锁并行组 B 的所有任务。

---

### 并行组 B（业务逻辑层）

**包含任务**：Task-002、Task-003、Task-004

**说明**：以下三个任务均依赖 Task-001（数据库表结构），但彼此之间相互独立，可由不同开发人员同时并行开发：

- **Task-002**（付款申请 CRUD 接口）：负责申请单的增删改查，不涉及审批流程逻辑。
- **Task-003**（审批流程接口）：负责提交审批、审批通过/拒绝、撤回等状态流转接口，不依赖 Task-002 的具体实现。
- **Task-004**（权限控制与数据隔离）：负责 Spring Security 权限注解配置和数据行级隔离，可与 Task-002、Task-003 并行开发，最终合并时注意接口权限注解的一致性。

> **注意**：并行开发时需提前约定好接口契约（DTO 类名、字段名），避免合并冲突。

---

### 并行组 C（集成与测试层）

**包含任务**：Task-005、Task-006

**说明**：以下两个任务可在并行组 B 完成后同时进行：

- **Task-005**（集成消息通知服务）：依赖 Task-003 的审批流程接口，在审批状态变更时触发消息通知。
- **Task-006**（单元测试与集成测试）：依赖 Task-002 和 Task-003 的核心业务逻辑实现，编写测试用例并达到覆盖率要求。

---

### 并行组 D（验收层）

**包含任务**：Task-007

**说明**：联调与冒烟测试需要所有功能开发完成后才能进行，是整个 CR 的最终验收环节。测试通过后方可提交发版申请。

---

## 串行任务说明

以下任务链必须严格按顺序串行执行，不可跳过或并行：

### 主干串行链

```
Task-001 → [Task-002 / Task-003 / Task-004（并行）] → [Task-005 / Task-006（并行）] → Task-007
```

| 串行约束 | 原因说明 |
|----------|----------|
| Task-001 必须先于 Task-002/003/004 | 数据库表不存在时，业务代码无法编译通过（实体类映射失败） |
| Task-002/003 必须先于 Task-006 | 测试用例依赖被测接口的具体实现，接口未完成无法编写有效测试 |
| Task-003 必须先于 Task-005 | 消息通知需要在审批状态变更的事件中触发，审批接口未完成无法集成 |
| Task-005/006 必须先于 Task-007 | 联调测试需要所有功能（含通知）完成，且单元测试通过后才能进行端到端验收 |
