## 一、背景分析

### 1.1 项目背景

SPMP 智慧物业管理平台的用户中心模块（`com.spmp.user`），负责系统的身份认证和权限控制。该模块是所有业务模块的基础依赖，为工单、缴费、公告、门禁等模块提供用户身份和权限支持。

### 1.2 已有基础设施（common 模块已完成）

以下能力已在 common 模块中实现，user-center 可直接使用：

| 组件 | 说明 | 状态 |
|------|------|------|
| SecurityConfig | Spring Security 配置，JWT 无状态认证，白名单路径 | ✅ 已完成 |
| JwtTokenProvider | JWT 令牌生成/解析/验证，支持 admin/owner 分端过期 | ✅ 已完成 |
| JwtAuthenticationFilter | JWT 认证过滤器 | ✅ 已完成 |
| DataPermissionInterceptor | 数据权限 SQL 拦截器（四级：全部→片区→小区→楼栋） | ✅ 已完成 |
| @DataPermission | 数据权限注解 | ✅ 已完成 |
| DataPermissionContext | 数据权限上下文 | ✅ 已完成 |
| BCryptPasswordEncoder | 密码编码器 | ✅ 已完成 |
| Result / PageResult | 统一响应包装 | ✅ 已完成 |
| ErrorCode / BusinessException | 错误码和业务异常 | ✅ 已完成 |
| GlobalExceptionHandler | 全局异常处理 | ✅ 已完成 |
| BaseEntity | 公共字段 + 自动填充 | ✅ 已完成 |
| RedisUtils | Redis 缓存工具 | ✅ 已完成 |
| EncryptUtils | 敏感数据加解密 | ✅ 已完成 |

### 1.3 与 domain-share 参考文档的关系

domain-share 目录下的文档来自参考系统（雨虹/YH 内部框架），包含多租户、365/SAP/OA 集成、内部/外部员工身份区分等内容。**以下内容不适用于 SPMP**：

| 参考系统概念 | SPMP 处理方式 |
|-------------|--------------|
| tenant_id（多租户） | ❌ 不需要，SPMP 为单租户系统 |
| 内部员工/外部员工身份区分 | ❌ 不需要，SPMP 统一用户模型 |
| 365/SAP/OA 系统集成 | ❌ 不需要，SPMP 无外部用户数据同步 |
| 机构管理（organ） | ❌ 不需要，SPMP 通过数据权限关联片区/小区/楼栋 |
| 岗位管理（position） | ❌ 不需要 |
| 用户组管理（user_group） | ❌ 不需要 |
| Feign/HSF 远程调用 | ❌ 不需要，SPMP 为单体应用，模块间通过 api 包接口调用 |

### 1.4 SPMP 用户角色

| 角色 | 客户端 | 数据权限级别 | 说明 |
|------|--------|-------------|------|
| 超级管理员 | PC | 全部 | 系统全局管理 |
| 物业管理员 | PC | 小区 | 所管辖小区的日常管理 |
| 片区经理 | PC | 片区 | 所辖片区多个小区的监管 |
| 楼栋管家 | PC | 楼栋 | 具体楼栋的日常管理 |
| 维修人员 | PC | 仅本人 | 处理分配的报修工单 |
| 业主 | H5 | 仅本人 | 移动端物业交互 |

### Q2：数据权限级别 - "仅本人"

[Question] CR02 草稿中提到了五级数据权限（全部/片区/小区/楼栋/仅本人）。common 模块的 DataPermissionInterceptor 目前支持四级（全部/片区/小区/楼栋）。是否需要增加"仅本人"级别？维修人员和业主的场景确实需要"仅本人"数据过滤。

[Answer] 增加

### Q3：业主登录方式

[Question] 业主（H5 端）的登录方式有以下选项：
- A：用户名 + 密码（与 PC 端一致）
- B：手机号 + 短信验证码
- C：手机号 + 密码
- D：同时支持 A 和 B

CR02 草稿中提到 H5 端使用"手机号 + 密码"。请确认业主端的登录方式。

### Q4：密码策略
