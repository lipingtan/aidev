## 澄清问题

### 功能性问题

#### wo_01 — 报修类型与扩展性

草稿中报修类型为：水电维修、门窗维修、管道疏通、公共设施、其他。

**[Question]** 报修类型是使用硬编码枚举，还是复用 base-center 的字典管理（base_dict）来维护？后续是否需要支持自定义报修类型？

**[Answer]** 
1. 报修类型建议使用 base-center 的字典管理（base_dict）来维护，后续可以方便地扩展新的报修类型。
2. 报修类型枚举值建议与 base-center 中的字典值保持一致，避免重复定义。

#### wo_02 — 报修地址与公共区域

草稿中报修地址默认绑定业主房屋，但业主可能报修公共区域问题（如楼道灯坏了、小区路面破损）。

**[Question]** 
1. 是否支持公共区域报修？如果支持，报修地址如何选择？
2. 公共区域报修的地址粒度是什么（小区级 / 楼栋级 / 单元级）？

**[Answer]** 
1. 支持公共区域报修，报修地址选择公共区域。
2. 公共区域报修地址建议绑定小区房屋，地址粒度为楼栋级或单元级。

#### wo_03 — 工单派发规则

草稿中提到手动选择维修人员派发。

**[Question]**
1. 是否需要支持自动派发规则（如按楼栋分配、按维修人员工作量均衡分配、按报修类型匹配技能）？
2. 维修人员的数据来源：是通过 UserApi 查询特定角色（如 `REPAIR_STAFF`）的用户，还是有独立的维修人员管理？
3. 一个工单是否可以多次转派？转派次数是否有限制？

**[Answer]** 
1. 支持自动派发规则，如按楼栋分配、按维修人员工作量均衡分配、按报修类型匹配技能。
2. 维修人员的数据来源建议通过 UserApi 查询特定角色（如 `REPAIR_STAFF`）的用户。
3. 一个工单可以多次转派，转派次数无限制。

#### wo_07 — 工单取消规则

**[Question]**
1. 哪些状态下可以取消工单？（待派发、待接单可以取消，处理中、待验收是否也可以取消？）
2. 取消工单需要填写取消原因吗？
3. 业主可以取消自己的工单吗？还是只有物业管理员才能取消？

3. 业主可以取消自己的工单，物业管理员也可以取消。
4. 已派发的工单取消后，需要通知维修人员。

#### wo_nfr_02 — 并发与性能

**[Question]**
1. 预计每日工单量级是多少？（用于评估数据库索引和缓存策略）
