# 回归防护规范（Regression Guard）

> 核心理念：每次变更不仅要定义"做什么"，还要定义"不能破坏什么"。

---

## 一、为什么需要回归防护

在 AI 执行任务时，如果只关注"新增功能"而不明确"不能破坏什么"，容易出现：
- 修改公共组件时影响其他模块
- 新增逻辑覆盖了已有的边界处理
- 接口签名变更导致调用方报错
- 配置变更影响其他环境

Bugfix 流程已有"不变行为（回归防护）"的三段式描述，本规范将其推广到所有 CR。

---

## 二、适用范围

| CR 类型 | 是否需要回归防护 |
|---------|:---:|
| normalCR（涉及跨模块） | ✅ 必须 |
| normalCR（单模块内） | ✅ 必须（可简化） |
| minorCR | ⚠️ 视情况（涉及公共组件时必须） |
| Bugfix | ✅ 已有（不变行为章节） |

---

## 三、在 design.md 中的体现

每个 CR 的 design.md 必须包含「不变行为清单」章节，位于正确性属性之后：

```markdown
## 不变行为清单（回归防护）

本次变更不应影响以下已有功能：

| 编号 | 不变行为 | 验证方式 | 涉及模块 |
|------|----------|----------|----------|
| RG-1 | 现有用户登录流程不受影响 | 登录接口返回正常 token | user-center |
| RG-2 | 现有数据权限过滤逻辑不变 | 不同角色查询结果范围正确 | common |
| RG-3 | 现有 Redis 缓存 Key 格式不变 | 缓存命中率不下降 | base-center |
| RG-4 | 现有 API 接口签名向后兼容 | 旧版客户端调用不报错 | 所有模块 |
```

### 编写规则

1. **格式**：`WHEN <已有场景> THEN 系统 SHALL CONTINUE TO <保持行为>`
2. **来源**：从以下维度检查是否有不变行为需要声明：
   - 本次修改的文件被其他模块引用的情况
   - 本次修改的接口有外部调用方
   - 本次修改的配置影响其他环境或模块
   - 本次修改的公共组件被多处使用
3. **粒度**：每个不变行为对应一个可验证的检查点

---

## 四、在 tasks.md 中的体现

不变行为清单中的每一项，必须被分配到至少一个 Task 的 Acceptance 中作为回归验证项：

```markdown
**Acceptance（验证标准）:**
- [ ] 新增 XSS 过滤器正常工作
- [ ] getDiagnostics 零错误
- [ ] 【回归】现有登录接口不受 XSS 过滤影响（RG-1）
- [ ] 【回归】现有文件上传接口正常工作（RG-3）
```

标注格式：`【回归】描述（RG-编号）`

---

## 五、回归防护检查清单

AI 在以下时机必须执行回归检查：

### design.md 生成时

- [ ] 是否列出了所有可能受影响的已有功能
- [ ] 每个不变行为是否有明确的验证方式
- [ ] 是否覆盖了跨模块影响

### tasks.md 生成时

- [ ] 每个 RG 项是否被分配到至少一个 Task 的 Acceptance 中
- [ ] 高复杂度任务是否在 Constraints 中引用了相关 RG 项

### Task 执行后

- [ ] 所有标注【回归】的 Acceptance 项是否验证通过
- [ ] 如果无法自动验证，是否标注"需人工确认"

---

## 六、常见回归风险场景

| 变更类型 | 常见回归风险 | 防护措施 |
|----------|-------------|----------|
| 修改 SecurityConfig | 其他接口的权限控制失效 | 验证白名单和权限注解不受影响 |
| 修改公共 DTO/VO | 其他模块序列化/反序列化失败 | 验证所有引用方编译通过 |
| 修改 MyBatis XML | 其他查询语句受影响 | 验证相关 Mapper 方法正常 |
| 新增全局 Filter/Interceptor | 现有请求链路被拦截 | 验证现有接口响应正常 |
| 修改 application.yml | 其他 profile 配置失效 | 验证各环境配置加载正确 |
| 修改公共工具类 | 其他调用方行为变化 | 验证所有调用方逻辑不变 |

---

## 七、与 Bugfix 三段式的关系

Bugfix 的三段式已包含回归防护：

```
当前行为（缺陷）：WHEN ... THEN <错误表现>
期望行为（正确）：WHEN ... THEN 系统 SHALL <正确行为>
不变行为（回归）：WHEN ... THEN 系统 SHALL CONTINUE TO <保持行为>  ← 这就是回归防护
```

本规范将第三段的思想推广到所有 CR 的 design.md 中，确保新功能开发也有明确的回归防护意识。
