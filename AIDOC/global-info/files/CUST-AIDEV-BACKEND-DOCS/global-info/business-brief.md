## 项目背景

本系统是智慧物业管理平台（SPMP - Smart Property Management Platform），旨在为物业公司提供数字化管理工具，提升物业服务效率和业主满意度。平台覆盖业主管理、报修工单、缴费账单、社区公告、门禁管理等核心业务场景。

**系统名称：** 智慧物业管理平台（SPMP）

**所属业务线：** 物业管理部、客户服务部、财务部

**系统定位：**

智慧物业管理平台是连接物业公司与业主的核心业务平台，主要解决以下问题：
- 业主信息和房产数据的统一管理
- 报修工单的在线提交、派发和全流程跟踪
- 物业费、停车费、水电费等费用的在线账单和支付
- 社区公告和通知的精准推送
- 访客预约和门禁记录的数字化管理
- 基于角色和数据范围的精细化权限控制

**关联系统：**

| 系统名称 | 关系类型 | 说明 |
|----------|----------|------|
| 微信支付/支付宝 | 下游集成 | 在线缴费支付渠道 |
| 短信平台 | 下游集成 | 通知短信发送 |
| 门禁硬件系统 | 双向集成 | 门禁开关控制、通行记录同步 |
| 财务系统 | 上游依赖 | 财务数据对账 |

## 用户需求

### 目标用户群体

| 用户角色 | 角色描述 | 核心诉求 |
|----------|----------|----------|
| 超级管理员 | 系统全局管理，负责角色权限配置和系统设置 | 灵活的权限配置、系统运行监控 |
| 物业管理员 | 负责所管辖小区的日常物业管理 | 高效处理工单、管理缴费、发布公告 |
| 片区经理 | 负责所辖片区多个小区的业务监管 | 跨小区数据查看、审批、统计分析 |
| 楼栋管家 | 负责具体楼栋的日常管理和业主沟通 | 工单派发、缴费催收、业主沟通、门禁审批 |
| 维修人员 | 负责处理分配的报修工单 | 快速接单、反馈维修进度、上传维修结果 |
| 业主 | 小区住户，使用移动端进行日常物业交互 | 在线报修、缴费、查看公告、访客预约 |

### 核心功能需求

1. **用户与权限管理**：支持 RBAC 角色权限模型，功能权限（菜单+按钮）和数据权限（全部→片区→小区→楼栋）四级控制
2. **业主管理**：业主信息维护、房产绑定、家庭成员管理、业主认证
3. **工单管理**：报修工单在线提交、自动/手动派发、流转跟踪、满意度评价
4. **缴费管理**：账单生成、在线支付、缴费催收、收费统计
5. **公告管理**：社区公告发布、精准推送、已读管理
6. **门禁管理**：访客预约、临时通行证、门禁记录查询

### 非功能性需求

- **性能要求：** 核心接口响应时间 P99 < 500ms，支持并发用户数 ≥ 300
- **可用性要求：** 系统可用性 ≥ 99.9%
- **安全要求：** 所有接口需通过统一认证网关，敏感数据字段需加密存储
- **兼容性要求：** PC 端支持 Chrome 90+、Edge 90+；H5 端支持微信内置浏览器、主流移动浏览器

## 业务挑战

### 业务挑战

1. **多层级数据权限控制**

   系统需要支持全部→片区→小区→楼栋四级数据权限，不同角色看到的数据范围不同，需要在查询层面高效实现数据隔离。

2. **工单流转流程复杂**

   工单从业主提交到最终完结涉及多个环节（提交→派发→接单→处理→验收→评价），需要支持自动派发规则和手动调度。

3. **缴费对账准确性**

   物业费、停车费、水电费等多种费用类型，需要保证账单生成和支付对账的准确性。

### 技术约束

- 前后端代码分离，独立部署
- 数据库变更需通过 DBA 审核
- 所有外部服务调用必须通过 API 网关
- 禁止自动 git 提交，确认当前代码分支必须是 feature 开头的分支才能提交

### 已知风险

| 风险描述 | 影响程度 | 应对措施 |
|----------|----------|----------|
| 门禁硬件厂商接口不稳定 | 中 | 实现熔断降级，关键操作增加重试 |
| 支付渠道回调延迟 | 中 | 增加定时对账任务，补偿机制 |
| 多小区数据量增长快 | 低 | 合理设计索引，预留分库分表方案 |
