# Refactor 技能

## 使用场景

- 功能实现后，对代码进行质量提升
- 发现方法过长、类职责不清时
- 存在大量重复代码需要抽取公共逻辑时
- 性能瓶颈排查后需要优化实现方式时

## 核心重构规则

### 识别坏味道

- **过长方法**：方法超过 80 行，拆分为多个职责单一的私有方法
- **过大类**：类超过 500 行或承担多个职责，按职责拆分
- **重复代码**：相同逻辑出现 2 次以上，抽取为工具方法或父类方法
- **过长参数列表**：参数超过 5 个，封装为 Request/Param 对象
- **魔法数字**：直接使用数字字面量，提取为命名常量或枚举
- **深层嵌套**：if/for 嵌套超过 3 层，使用卫语句（early return）或策略模式

### 重构手法

- **提取方法**：将代码块提取为独立方法，方法名体现意图
- **提取类**：将相关字段和方法提取为新类
- **引入参数对象**：多个相关参数封装为一个对象
- **以多态替换条件**：大量 if-else/switch 按类型分支，改用策略模式或工厂模式
- **内联临时变量**：只使用一次的临时变量，直接内联表达式
- **分解条件表达式**：复杂布尔条件提取为命名方法，提升可读性

### 后端重构要点（Java/Spring Boot）

- Service 层只做业务编排，不写 SQL 逻辑
- Mapper 层只做数据访问，不写业务判断
- 工具类方法设为 `static`，工具类构造器设为 `private`
- 枚举替代魔法字符串常量
- Builder 模式替代多参数构造器

### 前端重构要点（Vue）

- 超过 300 行的组件拆分为子组件
- 重复的响应式逻辑提取为 Composable
- 复杂模板表达式提取为 computed
- 重复的 API 调用逻辑封装为统一的 service 函数
