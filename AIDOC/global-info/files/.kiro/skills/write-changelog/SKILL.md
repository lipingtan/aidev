# Write Changelog 技能

## 使用场景

- 完成一个开发任务后，生成对应的 change-log
- 提交 PR 前整理变更记录
- 版本发布前汇总所有变更

## 文档规范

参考项目 `spec/normalCR/CRxx-示例需求名/change-log/` 目录下的文档格式。

### change-log 文档结构

```markdown
# Task-{编号}-{任务名} Change Log

## 基本信息

| 字段 | 内容 |
|------|------|
| 任务编号 | Task-001 |
| 任务名称 | xxx |
| 开发人员 | [开发者] |
| 完成时间 | YYYY-MM-DD |
| 关联需求 | CRxx-需求名 |

## 变更概述

简要描述本次变更的目的和范围。

## 变更详情

### 新增

- `文件路径`：说明新增内容

### 修改

- `文件路径`：说明修改内容（修改前 → 修改后）

### 删除

- `文件路径`：说明删除原因

## 数据库变更

### DDL 变更

- 无 / 新增表 xxx / 新增字段 xxx

### DML 变更

- 无 / 初始化数据 xxx

## 影响范围

- 影响的模块或功能点
- 是否有接口变更（是/否，如有请列出）
- 是否需要配置变更（是/否，如有请说明）

## 测试说明

- 测试类型：单元测试 / 接口测试 / 手工测试
- 测试结论：通过 / 部分通过（说明原因）
```

## 生成步骤

1. 读取对应的 Task 文档（`task/Task-xxx.md`）了解任务内容
2. 分析代码变更（可结合 git diff 或文件列表）
3. 按模板填写各变更分类
4. 明确标注数据库变更和影响范围

## 注意事项

- 文件命名：`Task-{编号}-{任务名}-change-log.md`
- 变更描述要具体，避免"修改了一些代码"这类模糊描述
- 数据库变更必须单独列出，便于 DBA 审查
- 影响范围要如实填写，不遗漏接口变更
