# 日志分析器 (Log Analyzer)

## 概述

通用型日志根因分析技能，通过AI智能分析应用日志，自动识别问题并提供可执行的修复建议。

## 核心功能

- 📊 **多维度分析**：异常、性能、依赖、业务逻辑
- 🔍 **智能格式检测**：自动识别JSON、文本日志和框架格式
- ⏱️ **时间窗口关联**：重构事件时间线和因果链
- 🎯 **证据驱动**：为每个根因假设提供置信度和证据链
- 💡 **可执行建议**：立即、短期、长期的行动计划

## 使用场景

```bash
# 基本用法 - 分析日志文件
/log-analyzer /path/to/application.log

# 指定时间范围分析事故
/log-analyzer app.log --since "2025-01-29 10:00" --until "2025-01-29 11:00"

# 聚焦性能问题
/log-analyzer app.log --focus performance

# 跨服务关联分析
/log-analyzer api.log --correlate-with service.log,db.log

# 与基线对比
/log-analyzer incident.log --baseline normal.log --compare
```

## 分析维度

### 1. 异常与错误分析
- 识别高频异常和错误模式
- 构建错误传播链
- 区分根因异常和级联错误
- 定位代码热点

### 2. 性能分析
- 识别慢请求和性能瓶颈
- 检测响应时间异常
- 发现资源耗尽迹象
- 性能回归告警

### 3. 依赖分析
- 识别外部服务失败
- 分析超时和连接问题
- 检测级联故障模式
- 构建服务依赖图

### 4. 业务逻辑分析
- 分析工作流失败
- 检测数据不一致
- 识别验证失败模式
- 追踪状态转换问题

## 输出报告示例

生成的Markdown报告包含：

```markdown
## 根因分析摘要

**分析时段：** 2025-01-29 10:00:00 - 11:00:00 UTC
**置信度：** 高

### 主要根因
数据库连接池耗尽（置信度：92%）

### 证据链
- 10:00:15 - 首次连接超时错误
- 10:00:23 - 连接池耗尽
- 10:00:30 - API层级联故障

### 建议
- 立即：增加连接池大小到100
- 短期：添加监控告警
- 长期：优化慢查询和索引
```

## 支持的日志格式

- ✅ JSON结构化日志
- ✅ 文本日志（常见格式）
- ✅ Spring Boot (Logback)
- ✅ Django (Python)
- ✅ Node.js (Winston/Bunyan)
- ✅ Go (Zap/Logrus)
- ✅ .NET (Serilog)

## 最佳实践

### ✅ 推荐

1. **提供充足上下文**
   - 包含事故前30分钟和事故后15分钟的日志
   - 更多数据 = 更准确的关联分析

2. **包含所有相关服务**
   - API网关、应用服务器、数据库、消息队列、缓存

3. **保留所有日志级别**
   - DEBUG日志提供有价值的上下文
   - INFO日志显示正常流程

4. **使用关联ID**
   - 启用请求跟踪以跨服务追踪问题

### ❌ 避免

1. 只分析ERROR日志（会丢失上下文）
2. 忽略时间戳（无法关联事件）
3. 过早过滤DEBUG日志
4. 孤立分析单个服务
