# SQL Review 技能

## 使用场景

- 提交 DDL/DML 变更前进行审查
- 慢查询排查和优化
- 新增 MyBatis Mapper 语句审查
- 数据库设计评审

## 审查规则

### DDL 规范

**表设计**
- 表名、字段名使用小写下划线命名，如 `user_order`、`create_time`
- 每张表必须有主键，推荐使用 `BIGINT UNSIGNED AUTO_INCREMENT` 或雪花 ID
- 必须包含审计字段：`create_time`、`update_time`、`create_by`、`update_by`
- 推荐包含逻辑删除字段：`is_deleted TINYINT(1) DEFAULT 0`
- 字段必须有 `COMMENT`，表必须有 `COMMENT`
- 字符集统一使用 `utf8mb4`，排序规则使用 `utf8mb4_unicode_ci`

**索引设计**
- 频繁查询的字段必须建索引
- 联合索引遵循最左前缀原则，高选择性字段放左边
- 索引数量不超过 5 个（写多读少的表适当减少）
- 禁止在低选择性字段（如性别、状态）上单独建索引
- 外键字段必须建索引

### DML 规范

**查询安全**
- 禁止 `SELECT *`，必须明确列出查询字段
- 查询必须有 WHERE 条件，禁止全表扫描
- 分页查询必须有 ORDER BY，避免结果不稳定
- 大偏移量分页（OFFSET > 10000）改用游标分页

**更新/删除安全**
- UPDATE/DELETE 必须有 WHERE 条件
- 批量操作超过 500 条需分批执行
- 生产环境执行前必须先 SELECT 确认影响行数
- 重要数据删除使用逻辑删除，不物理删除

**性能规范**
- 避免在 WHERE 条件中对字段使用函数，会导致索引失效
  - ❌ `WHERE DATE(create_time) = '2024-01-01'`
  - ✅ `WHERE create_time >= '2024-01-01' AND create_time < '2024-01-02'`
- 避免隐式类型转换，字符串字段用字符串值查询
- JOIN 不超过 3 张表，超过则考虑业务拆分或冗余字段
- 子查询优先改写为 JOIN

## 审查清单

### DDL 审查

- [ ] 表名、字段名命名规范
- [ ] 主键设计合理
- [ ] 必要审计字段齐全
- [ ] 字段有 COMMENT
- [ ] 字符集正确
- [ ] 索引设计合理，无冗余索引
- [ ] 字段类型选择合理（不过度设计长度）

### DML 审查

- [ ] 无 `SELECT *`
- [ ] 有 WHERE 条件限制范围
- [ ] 批量操作有分批处理
- [ ] 无函数包裹索引字段
- [ ] 无隐式类型转换
- [ ] JOIN 数量合理
