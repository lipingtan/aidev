# Bugfix 需求文档 — Fix-001 第0批次（业务逻辑错误优先）

## 1. 范围与目标

本批次仅处理 `bugfix-plan-v2.md` 中定义的第0批次业务逻辑问题：

- 后端：`B-10`、`B-17`、`B-18`、`B-19`
- 前端：`F-01`、`F-05`、`F-08`、`F-09`、`F-10`、`F-12`

目标：优先恢复关键业务流程闭环、状态一致性与业务规则正确性。

---

## 2. 三段式需求（当前行为 / 期望行为 / 不变行为）

### 2.1 支付链路与账单状态

**当前行为（缺陷）**  
WHEN 业主在 H5 账单详情点击支付 THEN 前端直接触发支付回调接口，且后端支付并发与归属校验不足，可能出现未真实支付即成功、并发状态竞争、越权查询支付详情、退款金额超额。

**期望行为（正确）**  
WHEN 业主发起支付与回调处理 THEN 系统 SHALL 仅通过受控回调路径更新支付状态，并确保支付创建/回调幂等、支付详情按 owner 归属校验、退款金额不得超过可退额度。

**不变行为（回归防护）**  
WHEN 正常支付成功或失败 THEN 系统 SHALL CONTINUE TO 保持现有账单状态流转语义（UNPAID/OVERDUE/PAYING/PAID/CANCELLED/REFUNDED）与现有对账、记录查询接口契约兼容。

（对应：`F-05`、`B-17`、`B-18`、`B-19`）

### 2.2 公告可见性与重推覆盖

**当前行为（缺陷）**  
WHEN 公告发布给业主并执行重推 THEN 系统仅对已认证快照用户有效，新注册或后认证业主可能不可见且重推无效。

**期望行为（正确）**  
WHEN 公告发布或重推 THEN 系统 SHALL 覆盖业务定义内的目标业主，并在重推前补齐必要快照，确保目标用户可见与可触达。

**不变行为（回归防护）**  
WHEN 公告处于非发布态或超出目标范围 THEN 系统 SHALL CONTINUE TO 保持现有审批流、状态机与非目标用户不可见约束。

（对应：`B-10`，主计划引用 notice-center Fix-001）

### 2.3 前端登录态/初始化态/认证门禁一致性

**当前行为（缺陷）**  
WHEN token 过期、初始化检查失败、或业主未完成认证 THEN 前端存在状态清理不一致、fail-open 放行、门禁缺失、响应解包误用与首页硬编码展示，导致流程误导和行为偏差。

**期望行为（正确）**  
WHEN 触发上述场景 THEN 系统 SHALL 统一清理登录态、严格初始化门禁、按认证状态控制页面可达性、统一响应解包契约，并展示真实业务数据或明确空态。

**不变行为（回归防护）**  
WHEN 用户处于正常登录且权限满足 THEN 系统 SHALL CONTINUE TO 保持现有导航流程、页面主交互与已定义接口结构不被破坏。

（对应：`F-01`、`F-08`、`F-09`、`F-10`、`F-12`）

## 4. 验收标准（第0批次）

- 支付：不存在前端可直接达成“支付成功”的路径；并发与归属校验通过。
- 公告：目标业主可见性与重推覆盖满足业务定义。
- 前端状态：401、初始化、认证门禁、响应解包、首页展示表现一致且可解释。
- 回归：核心路径（登录、支付、公告、首页）可通过手工与自动化用例验证。
