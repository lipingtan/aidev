# 案例库

> 记录每次实际生成的经验，包括成功和失败案例。
> 这是知识库中最有价值的部分——来自真实实践的验证。

## 目录结构

```
cases/
├── README.md           # 本文件
├── success/            # 成功案例（效果好的提示词）
│   └── case-NNN.md
└── failure/            # 失败案例（效果差 + 原因分析）
    └── case-NNN.md
```

## 案例编号规则

- 格式：`case-NNN`（三位数字，从 001 开始）
- 成功和失败分别编号
- 文件名：`case-001.md`、`case-002.md`...

## 案例记录模板

```markdown
# 案例 NNN：[简短标题]

## 基本信息

| 项目 | 值 |
|------|-----|
| 引擎 | KLING 3.0 / WAN 2.5 |
| 场景类型 | 对话/动作/情绪/转场/氛围 |
| 日期 | YYYY-MM-DD |
| 结果 | 成功/失败 |
| 项目 | [来自哪个系列/单集] |

## 使用的提示词

### Master Prompt / 整体描述
（完整提示词）

### Shot Prompts
（完整的分镜提示词）

## 效果描述

（生成结果的描述）
- 好的方面：
- 不好的方面：

## 关键发现

（从这次生成中学到了什么）

## 可复用的模式

（如果是成功案例，提炼出可复用的写法）

## 需要避免的写法

（如果是失败案例，记录需要避免的写法）

## 标签

#tag1 #tag2 #tag3
```

## 何时记录案例

1. **必须记录**：
   - 发现了新的有效模式
   - 遇到了之前没见过的问题
   - 找到了某个问题的解决方案

2. **建议记录**：
   - 效果特别好的生成
   - 效果特别差的生成
   - 尝试了新的写法

3. **不需要记录**：
   - 常规生成，效果符合预期
   - 已知问题的重复出现
