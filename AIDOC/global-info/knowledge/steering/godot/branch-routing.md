# 2D/3D 分支路由规范

> 本文件为引擎无关的通用版本，定义 2D/3D 选择规则和混合模式。
> 具体引擎节点映射和代码示例参见对应引擎目录（如 `godot/godot-engine.md` 第五节）。

---

## 一、6 个分支节点的 2D/3D 对比表

### 1.1 场景搭建

| 维度 | 坐标系 | 单位 | 场景组织 | 典型工作流 |
|------|--------|------|----------|-----------|
| **3D** | XYZ 三轴 | 1单位=1米 | 按功能分层（地形/建筑/道具/NPC） | 灰盒→白盒→美术替换 |
| **2D** | XY 二轴 | 像素 | 按图层分层（背景/中景/前景/UI） | 概念图→切图→拼接→动画 |

**3D 场景搭建流程：**
1. 创建根节点
2. 配置环境（天空盒、环境光）
3. 添加主光源
4. 搭建地形（网格/CSG/导入模型）
5. 放置碰撞体
6. 配置导航网格
7. 放置交互区域

**2D 场景搭建流程：**
1. 创建根节点
2. 添加视差背景
3. 添加瓦片地图层（地形/碰撞/装饰）
4. 放置精灵对象
5. 配置碰撞
6. 配置导航
7. 放置交互区域

### 1.2 角色控制器

| 维度 | 移动方式 | 碰撞形状 | 动画系统 | 输入处理 |
|------|----------|----------|----------|----------|
| **3D** | 三轴移动+滑动 | 胶囊体/盒体 | 骨骼动画+动画树 | 方向键→3D向量 + 鼠标→旋转 |
| **2D** | 二轴移动+滑动 | 胶囊/圆形 | 精灵帧动画 | 方向键→2D向量 |

### 1.3 相机系统

| 维度 | 跟随方式 | 视角控制 | 特殊处理 |
|------|----------|----------|----------|
| **3D** | 弹簧臂+偏移 | 鼠标控制俯仰/旋转 | 防穿墙、锁定目标 |
| **2D** | 平滑跟随 | 无旋转（或有限旋转） | 边界限制、屏幕震动 |

### 1.4 物理系统

| 维度 | 碰撞层 | 射线检测 | 力的应用 |
|------|--------|----------|----------|
| **3D** | 32层 3D碰撞 | 3D射线查询 | Vector3 力/冲量 |
| **2D** | 32层 2D碰撞 | 2D射线查询 | Vector2 力/冲量 |

**碰撞层规划**：统一遵守引擎规范中的碰撞层标准分配（1=PlayerHurtbox、2=EnemyHurtbox、3=PlayerHitbox、4=EnemyHitbox、5=Environment、6=Interactable、7=Projectile、8=Trigger）。2D 项目沿用相同编号，替换为 2D 实现类型。

### 1.5 光照系统

| 维度 | 光源类型 | 阴影 | 全局照明 | 性能考量 |
|------|----------|------|----------|----------|
| **3D** | 方向光/点光/聚光 | 实时+烘焙 | GI方案 | 阴影分辨率、光源数量 |
| **2D** | 点光/方向光 | 2D遮挡阴影 | 全局色调调制 | 光源数量、遮挡体复杂度 |

### 1.6 UI 系统

| 维度 | 布局方式 | 与游戏世界的关系 |
|------|----------|-----------------|
| **3D 游戏的 UI** | 锚点+容器自适应 | 通过独立画布层叠加在 3D 之上 |
| **2D 游戏的 UI** | 锚点+容器自适应 | 通过独立画布层叠加在 2D 之上 |
| **3D 世界内 UI** | 3D 空间定位 | 存在于 3D 空间中（血条、名牌） |

> UI 系统本身始终是 2D，区别在于它叠加在 3D 还是 2D 游戏世界之上。

## 二、3D 资产导入流程

### 2.1 五步骤流程

1. **格式验证**：检查格式（.glb/.gltf 优先）、文件大小（≤50MB）、多边形数（角色≤30K，环境≤100K，道具≤5K）
2. **导入配置**：设置缩放、轴向、动画分离、材质映射、LOD
3. **碰撞配置**：生成碰撞形状、设置碰撞层和掩码
4. **场景集成**：创建可实例化场景、添加子节点、配置脚本挂载点
5. **质量验证**：性能检查、视觉检查、交互功能检查、内存检查

### 2.2 导入配置速查

| 资产类型 | 动画 | 碰撞 | LOD | 材质 |
|----------|------|------|-----|------|
| 角色模型 | 分离为独立动画 | 胶囊体 | 3级 | PBR |
| 环境模型 | 无/简单 | 三角网格 | 2-3级 | PBR/烘焙 |
| 道具模型 | 无/简单 | 凸包 | 1-2级 | PBR |
| 武器模型 | 无 | 简化凸包 | 无 | PBR |
| 特效模型 | 顶点动画 | 无 | 无 | 自发光 |

## 三、2D AI 生成流程

### 3.1 五步骤流程

1. **提示词设计**：确定风格关键词、内容描述、技术参数、负面提示词
2. **批量生成**：同风格使用相同种子/风格锁定，每资产 3-5 变体
3. **后处理**：去背景、统一尺寸、色彩校正、边缘处理
4. **切图与动画**：精灵表切割、动画帧定义、九宫格切割、图集打包
5. **导入与验证**：导入引擎、创建动画资源、预览效果、检查内存

### 3.2 AI 生成质量评估标准

| 评估维度 | 合格标准 |
|----------|----------|
| 风格一致性 | 与项目美术风格 90%+ 匹配 |
| 细节完整性 | 主体完整、无缺失部分 |
| 边缘质量 | 边缘清晰、无毛刺 |
| 色彩协调 | 色调与项目调色板一致 |
| 尺寸适配 | 与游戏中其他元素比例协调 |

## 四、混合模式规范

### 4.1 3D 世界 + 2D UI（最常见）

```
场景树结构：
Root (3D)
├── World (3D)              # 3D 游戏世界
├── CanvasLayer (layer=1)   # HUD 层
└── CanvasLayer (layer=10)  # 菜单层（最上层）
```

规则：
- HUD 使用低层级画布（始终显示）
- 菜单使用高层级画布（覆盖一切）
- 3D 世界内 UI（血条、名牌）使用子视口+3D精灵
- UI 脚本与游戏逻辑脚本分离

### 4.2 3D 世界 + 2D 特效

规则：
- 3D 空间中的 2D 特效使用 Billboard 精灵
- 全屏后处理特效使用画布层 + Shader
- 粒子优先使用 GPU 粒子（性能更好）
- 序列帧特效用于复杂手绘动画效果

### 4.3 小地图

| 方案 | 做法 | 适用 |
|------|------|------|
| 实时渲染 | 子视口+正交相机俯视 | 小型关卡 |
| 预渲染+标记 | 静态地图图片+动态标记点 | 大型开放世界 |

坐标转换：3D 世界 XZ 平面 → 2D 小地图 XY 平面，按比例缩放+偏移。

## 五、节点选择决策流程

```
需要创建新内容？
├── 是 UI？ → 使用 UI 控件（始终 2D）
├── 是游戏世界内容？
│   ├── 项目主维度 3D → 使用 3D 节点
│   ├── 项目主维度 2D → 使用 2D 节点
│   └── 混合项目 → 根据该内容的空间需求决定
├── 是特效？
│   ├── 需要深度/遮挡 → 3D 粒子/精灵
│   └── 全屏/叠加 → 画布层 + 2D 节点
└── 是音频？
    ├── 需要空间衰减 → 空间音频节点
    └── 全局音频 → 非空间音频节点
```

### 常见错误

| 错误 | 正确做法 | 原因 |
|------|----------|------|
| 在 3D 场景中用 2D 精灵做血条 | 用子视口+3D精灵或画布层 | 2D 精灵不参与 3D 深度排序 |
| 用刚体做角色 | 用角色体 | 刚体难以精确控制 |
| UI 放在游戏世界节点下 | UI 放在独立画布层下 | 避免被游戏世界变换影响 |
| 用区域检测做地面碰撞 | 用静态体 | 区域不阻挡物体 |
