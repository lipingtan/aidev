# 开发工作流规范（通用）

> **写代码前**：先完成 **`pre-development-defaults.md`** 与 **`performance-budget.md`** 在项目中的落地（含 `QualitySettings`）。

## 概述

本文档定义了游戏开发的双轨并行工作流，涵盖从项目初始化到打磨优化的完整生命周期。
本文件为引擎无关的通用版本，具体引擎的补充规范请参见对应引擎目录下的工作流文件。

---

## 一、双轨并行工作流定义

### 1.1 轨道职责

| 轨道 | 核心职责 | 主要产出 | 负责人 |
|------|----------|----------|--------|
| **创意轨道** | 游戏设计、叙事策划、关卡设计、玩法设计、平衡评审 | GDD、世界观文档、角色设定、关卡策划、剧情大纲、对话脚本 | 策划/创意方 |
| **技术轨道** | 架构设计、代码实现、系统集成、资产集成、性能优化 | 脚本代码、场景文件、数据资源、着色器、插件 | 开发/AI |

### 1.2 并行原则

1. **独立推进**：两条轨道可各自前进，互不阻塞
2. **骨架先行**：技术轨道可先搭建系统骨架，等待创意轨道填充内容
3. **反馈修正**：技术轨道的可行性评估可反向修正创意轨道的设计
4. **同步对齐**：在关键节点进行双轨同步，确保方向一致

## 三、同步点触发规则

### 3.1 同步点定义

| 同步点 ID | 名称 | 触发条件 | 触发动作 | 阻塞规则 |
|-----------|------|----------|----------|----------|
| SYNC-01 | 世界观确认 | 创意轨道完成 worldview.md 并通过评审 | 技术轨道启动架构设计 | 技术轨道不得在此之前定义游戏特有数据结构 |
| SYNC-02 | 角色确认 | 创意轨道完成主角+核心敌人设定 | 技术轨道启动角色系统实现 | 角色系统接口可先定义，实现需等确认 |
| SYNC-03 | 关卡确认 | 创意轨道完成单个关卡的完整策划 | 技术轨道启动该关卡场景搭建 | 逐关卡触发，非全部完成才触发 |
| SYNC-04 | 叙事确认 | 创意轨道完成剧情大纲 | 技术轨道启动叙事系统实现 | 对话系统框架可先搭建 |
| SYNC-05 | 原型验证 | 技术轨道完成核心玩法原型 | 创意轨道评审操作手感 | 评审不通过则技术轨道需迭代 |
| SYNC-06 | 集成验证 | 技术轨道完成阶段性系统集成 | 双轨联合验收 | 验收不通过则定位问题归属轨道 |

### 3.2 触发流程

```
创意轨道完成产出物
    → 产出物写入 AIDOC/projects/{游戏名}/ 对应目录
    → 更新 tracker.md 状态为"已完成"
    → 通知技术轨道（同步点触发）
    → 技术轨道执行 PRE-CHECK（确认依赖文件存在）
    → 技术轨道开始执行
```

### 3.3 非阻塞前进规则

以下情况技术轨道可不等待同步点：
- 搭建系统骨架/接口（不含业务逻辑）
- 配置基础设施（目录、插件、工具链）
- 实现通用工具类（数学库、工具函数）
- 性能基准测试

## 四、门控机制

### 4.1 标准门控流程

```
plan（计划）
  → 明确要做什么、产出什么、写入哪里
  
澄清（Clarify）
  → 如有歧义，向用户提问确认
  → 无歧义则跳过此步
  
确认（Confirm）
  → 向用户展示执行计划摘要
  → 获得确认后执行
  
产出（Execute + Verify）
  → PRE-CHECK: 检查依赖和前置条件
  → EXECUTE: 生成产出物
  → POST-CHECK: 验证产出物质量
```

### 4.2 门控触发条件

| 操作类型 | 是否需要完整门控 | 说明 |
|----------|------------------|------|
| 创建新系统/模块 | ✅ 完整门控 | 影响范围大，需确认 |
| 修改已有接口 | ✅ 完整门控 | 可能破坏下游 |
| 填充数据/内容 | ⚠️ 简化门控 | plan + 产出，跳过澄清确认 |
| 修复 Bug | ⚠️ 简化门控 | 定位 + 修复 + 验证 |
| 格式调整/重构 | ❌ 无需门控 | 不改变行为的变更 |

### 4.3 PRE-CHECK 清单

```markdown
## PRE-CHECK
- [ ] 依赖文件存在: [列出所需文件]
- [ ] 前置任务完成: [列出前置任务及状态]
- [ ] 命名规范: 文件名 snake_case，≤64 字符
- [ ] 目录正确: 产出将写入 [目标目录]
- [ ] 接口兼容: [列出可能受影响的接口]
```

### 4.4 POST-CHECK 清单

```markdown
## POST-CHECK
- [ ] 语法正确: 脚本语法无错误
- [ ] 类型标注: 所有参数/返回值有类型
- [ ] 中文注释: 文件头 + 函数说明 + 关键逻辑
- [ ] 单一职责: 文件 ≤200 行
- [ ] 信号规范: 顶部声明，有注释
- [ ] 场景可加载: 场景文件可在编辑器打开
- [ ] 资源可序列化: 数据资源格式正确
```

## 五、设计→代码生成节奏规范

### 5.1 核心原则

**先横向铺接口，再纵向填实现，以"可独立验证"为最小生成单元。**

### 5.2 分层渐进策略

```
第一层：接口/骨架层（设计完一类就生成）
    │  设计完所有角色 → 生成角色系统接口 + 所有角色的数据骨架
    │  设计完关卡结构 → 生成关卡加载框架 + 场景骨架
    │  设计完道具列表 → 生成道具数据结构 + 注册表
    │
第二层：实现层（逐个填充）
    │  逐个角色：填充具体属性值、技能逻辑、动画配置
    │  逐个关卡：填充敌人配置、触发器、对话
    │  逐个道具：填充效果逻辑、视觉表现
    │
第三层：集成层（阶段性整合）
    │  一个关卡的所有元素就绪 → 集成测试 → 修复 → 确认
```

### 5.3 各设计对象的生成时机表

| 设计对象 | 生成时机 | 生成粒度 | 验证方式 | 理由 |
|----------|----------|----------|----------|------|
| **系统框架** | 该类设计全部完成后 | 一次性生成整个系统的接口+骨架 | 编译通过 + 接口可调用 | 确保接口一致性 |
| **角色个体** | 逐个设计完即生成 | 每个角色的数据资源+专属逻辑 | 测试场景中验证基础行为 | 可独立验证，互不阻塞 |
| **关卡** | 单个关卡设计完整后 | 该关卡的全部配置一次性生成 | 编辑器中运行该关卡 | 关卡内元素耦合度高 |
| **道具/技能** | 批量设计后批量生成 | 同类数据一起生成 | 批量验证效果触发 | 保持格式一致性 |
| **3D 资产** | 逐个导入 | 每个资产单独适配 | 编辑器中预览 | 依赖外部工具，周期长 |
| **2D 资产** | 批量生成 | 同风格一起生成 | 批量预览 + 尺寸检查 | AI 批量处理效率更高 |

### 5.4 生成节奏与门控的关系

| 层级完成事件 | 触发的门控 | 验证内容 |
|--------------|-----------|----------|
| 第一层（骨架）完成 | 架构设计 POST-CHECK | 接口一致性、命名规范、依赖关系正确 |
| 第二层（实现）每完成一个单元 | 单元级 POST-CHECK | 语法正确、类型完整、基础行为可验证 |
| 第三层（集成）完成 | 集成测试 POST-CHECK | 完整流程可跑通、无运行时错误 |

## 六、角色设计→代码生成流程

```
步骤 1: 设计所有角色的"共性"（属性结构、Component 定义）
    → 生成：角色系统框架代码（Component 基类、属性系统）
    → 验证：框架代码可编译、Component 可在编辑器中编辑

步骤 2: 逐个角色设计"个性"（具体数值、技能、行为）
    → 逐个生成：每个角色的数据文件 + 专属逻辑脚本
    → 每生成一个，在测试场景中验证基础行为

步骤 3: 角色间交互设计（组队、对抗、协作）
    → 生成：交互逻辑 + 集成测试场景
    → 验证：多角色同场景运行无冲突
```

## 七、关卡设计→代码生成流程

```
步骤 1: 设计关卡的"结构"（区域划分、流程节点、胜利条件）
    → 生成：关卡场景骨架 + 区域触发器 + 流程控制脚本
    → 验证：场景可加载，区域边界正确

步骤 2: 设计关卡的"内容"（敌人配置、道具放置、对话触发）
    → 整体生成：一个关卡设计完 → 一次性生成该关卡的全部配置数据
    → 验证：所有触发器可触发，敌人可生成

步骤 3: 集成验证
    → 在编辑器中运行该关卡，验证流程完整性
    → 从入口到出口可完整游玩
```

## 八、资产设计→集成流程

```
3D 资产：设计完一个 → 立即导入并配置（每个需单独适配碰撞/材质）
2D 资产：批量设计提示词 → 批量生成 → 批量后处理 → 批量导入
混合资产：先完成 3D 主体 → 再叠加 2D 特效/UI 层
```
