# 项目启动流程（通用）

> **开发前**：先读 **`pre-development-defaults.md`**（多平台画质、性能数字、`QualitySettings` 已定稿），再执行本节澄清与目录创建。

## 概述

本文档定义了从零启动一个新游戏项目的通用流程，确保项目结构规范、配置正确、可立即进入开发。
本文件为引擎无关的通用版本，具体引擎的初始化配置请参见对应引擎目录下的启动文件。

---

## 一、Phase 0 澄清问题列表

启动新项目时，必须先完成以下澄清。所有问题回答后才能进入目录创建阶段。

### 1.1 必填澄清项

| # | 问题 | 选项/格式 | 默认值 |
|---|------|-----------|--------|
| 1 | 游戏名称（英文 snake_case） | 字符串，≤32 字符 | 无（必填） |
| 2 | 游戏类型 | ARPG / 回合RPG / 动作 / 平台 / 解谜 / 混合 | ARPG |
| 3 | 目标平台 | PC / Mobile / Console / Web / 多平台 | PC |
| 4 | 主要维度 | 3D / 2D / 2.5D | 3D |
| 5 | 美术风格 | 写实 / 卡通 / 像素 / 低多边形 / 手绘 | 卡通 |
| 6 | 视角类型 | 第三人称 / 第一人称 / 俯视角 / 横版 / 自由 | 第三人称 |
| 7 | 预计规模 | 小型(1-5h) / 中型(5-20h) / 大型(20h+) | 中型 |
| 8 | 核心体验一句话 | 自由文本 | 无（必填） |
| 9 | 参考游戏（1-3个） | 游戏名 + 借鉴点 | 无（建议填写） |
| 10 | 是否需要 DLC 支持 | 是 / 否 | 是 |

### 1.2 可选澄清项

| # | 问题 | 选项/格式 | 默认值 |
|---|------|-----------|--------|
| 11 | 联机模式 | 单机 / 本地多人 / 在线多人 | 单机 |
| 12 | 物理精度需求 | 标准 / 高精度 | 标准 |
| 13 | 渲染管线 | 根据引擎选择对应管线 | 引擎默认 |
| 14 | 是否有已购素材包 | 是（列出）/ 否 | 否 |
| 15 | 目标帧率 | 30 / 60 / 120 | 60 |
| 16 | 是否需要叙事系统 | 是 / 否 | 是 |
| 17 | 是否需要存档系统 | 是 / 否 | 是 |
| 18 | 特殊技术需求 | 自由文本 | 无 |
| 19 | **若目标含移动：最低机型档位**（SoC / RAM / 系统） | 自由文本 | 无移动则填「不适用」 |
| 20 | **QualityProfile 档位** | 固定为 `desktop_high` + `mobile_high`（见 `performance-budget.md`）；**仅 PC** 项目在澄清中写「无移动」并只维护 `tier_desktop` |

### 1.3 澄清完成标准

- 必填项 1~10 全部有明确答案
- 答案无逻辑矛盾（如"2D"+"第三人称3D视角"需确认）
- 结果写入 `AIDOC/projects/{游戏名}/clarification.md`

## 二、目录骨架自动创建规则

### 2.1 创建触发条件

澄清问题全部回答完毕后，自动执行目录创建。

### 2.2 标准目录结构

根据澄清结果，创建以下目录结构：

```
# 文档目录
AIDOC/projects/{游戏名}/
├── design/
│   ├── gdd.md                    # 游戏设计文档
│   ├── worldview.md              # 世界观设定
│   ├── art-style.md              # 美术风格定义
│   ├── architecture.md           # 技术架构
│   ├── performance-budget.md     # 多平台帧率/显存/画质档（与 QualityProfile 对齐）
│   ├── balance.md                # 数值平衡
│   ├── characters/               # 角色设定目录
│   │   └── README.md
│   ├── levels/                   # 关卡策划目录
│   │   └── README.md
│   └── items/                    # 道具设计目录
│       └── README.md
├── narrative/                    # [如需叙事系统]
│   ├── outline.md                # 剧情大纲
│   ├── quests/                   # 任务设计
│   │   ├── main/
│   │   └── side/
│   └── dialogues/                # 对话脚本
├── iterations/                   # 迭代记录
│   └── README.md
├── clarification.md              # 澄清记录
└── tracker.md                    # 进度追踪

# 引擎工程目录（具体结构由引擎特定启动文件定义）
{引擎工程目录}/{游戏名}/
├── 引擎工程配置文件
├── scenes/                       # 场景文件
├── scripts/                      # 脚本
│   ├── core/                     # 核心系统
│   ├── gameplay/                 # 玩法逻辑
│   ├── ui/                       # UI 逻辑
│   ├── narrative/                # [如需叙事系统]
│   └── ai/                       # AI 行为
├── resources/                    # 数据资源
├── assets/                       # 游戏资产
├── plugins/                      # 插件
└── export/                       # 导出配置

# 资产源文件目录
assets_source/{游戏名}/
├── 3d_packages/                  # [如3D项目]
├── 2d_prompts/                   # [如含2D资产]
└── audio_raw/
```

### 2.3 条件创建规则

| 条件 | 创建的额外目录/文件 |
|------|---------------------|
| 主维度 = 3D | 3D 场景目录、3D 资产目录 |
| 主维度 = 2D | 2D 场景目录、精灵资产目录 |
| 需要叙事系统 | narrative/ 完整目录、scripts/narrative/ |
| 需要 DLC | DLC 目录、DLC 管理插件目录 |
| 联机模式 ≠ 单机 | scripts/network/、网络管理全局脚本 |
| 有已购素材包 | assets_source/{游戏名}/3d_packages/{包名}/ |

### 2.4 文件命名规则

- 所有目录和文件名使用 **英文 snake_case**
- 游戏名长度 ≤32 字符
- 单个文件名长度 ≤64 字符
- README.md 文件包含该目录的用途说明

## 三、快捷模式（已有部分设计时的跳过规则）

### 3.1 触发条件

当用户表示"已有部分设计"或提供了现有文档时，启用快捷模式。

### 3.2 跳过规则

| 已有内容 | 可跳过的步骤 | 仍需执行的步骤 |
|----------|-------------|----------------|
| 完整 GDD | 澄清问题中的类型/风格/规模 | 确认技术选型、创建目录 |
| 世界观文档 | Phase 1 创意轨道的世界观部分 | 技术架构仍需设计 |
| 角色设定 | Phase 2 创意轨道的角色设计 | 角色系统仍需实现 |
| 已有引擎工程 | 目录创建、工程配置 | 检查结构合规性、补充缺失目录 |
| 已购素材包 | 资产从零创建 | 素材包适配和导入流程 |
| 已有代码原型 | 从零搭建框架 | 代码审查 + 规范化重构 |

### 3.3 快捷模式流程

```
1. 用户声明已有内容
2. AI 检查已有内容的完整性和规范性
3. 生成差异报告：
   - 已满足的条件 ✅
   - 需要补充的内容 ⚠️
   - 不符合规范需修改的 ❌
4. 用户确认差异报告
5. 仅执行需要补充/修改的部分
6. 完成后执行标准 POST-CHECK
```

### 3.4 结构合规性检查

对已有工程执行以下检查：

```markdown
## 结构合规性检查
- [ ] 目录命名: 全部 snake_case
- [ ] 文档位置: 设计文档在 AIDOC/，代码在引擎工程目录
- [ ] 脚本规范: 有类名声明、类型标注、中文注释
- [ ] 场景组织: 按功能分类（关卡/角色/UI）
- [ ] 资源管理: 数据资源文件在资源目录下
- [ ] 全局单例: 全局脚本在指定目录下
```

## 四、启动完成检查清单

### 4.1 Phase 0 完成标准

以下所有项目全部通过，Phase 0 才算完成：

```markdown
## Phase 0 完成检查清单

### 澄清完成
- [ ] 游戏名称已确定（英文 snake_case，≤32字符）
- [ ] 游戏类型已确定
- [ ] 目标平台已确定
- [ ] 主要维度已确定（2D/3D/2.5D）
- [ ] 美术风格已确定
- [ ] 视角类型已确定
- [ ] 核心体验一句话已撰写
- [ ] clarification.md 已生成

### 目录结构
- [ ] AIDOC/projects/{游戏名}/ 完整创建
- [ ] 引擎工程目录完整创建
- [ ] assets_source/{游戏名}/ 完整创建
- [ ] 所有 README.md 包含目录用途说明
- [ ] 条件目录根据澄清结果正确创建/跳过

### 引擎工程
- [ ] 引擎工程配置文件正确（分辨率、渲染管线、物理）
- [ ] 全局单例脚本已注册
- [ ] 输入映射已根据游戏类型预配置
- [ ] 基础脚本骨架已生成
- [ ] 工程可在引擎编辑器中正常打开

### 文档初始化
- [ ] tracker.md 已创建，包含 Phase 0~5 进度模板
- [ ] gdd.md 已创建骨架（标题 + 章节结构）
- [ ] architecture.md 已创建骨架（技术选型已填写）

### 最终确认
- [ ] 用户确认项目方向正确
- [ ] 无逻辑矛盾（维度/视角/类型匹配）
- [ ] 可以进入 Phase 1
```

### 4.2 启动后的下一步指引

Phase 0 完成后，自动提示用户：

```
✅ 项目 {游戏名} 初始化完成！

下一步建议：
1. [创意轨道] 开始撰写 GDD（核心玩法循环、目标受众）
2. [创意轨道] 开始构建世界观（时代、地理、势力）
3. [技术轨道] 可同步开始技术架构设计

输入 "开始 Phase 1" 或指定具体任务继续。
```
