# AI 输出文档词汇优化规范（强制）

## 目的

消除 AI 生成文档中的典型"AI味"词汇，使产出文档读起来像人类专业人士撰写，而非机器生成。
本规范为语义级指导，非机械替换——需结合上下文选择最自然的表达。

**本规范为强制规范，所有 AI 产出的文档、回复、代码注释均须遵守。**

---

## 一、必须规避的词汇（明显 AI 生成痕迹）

| 规避词汇 | 替代方向 | 规避理由 |
|----------|----------|----------|
| 全景导航 | 报告结构 / 章节索引 / 目录 | "全景导航"是典型 AI 造词 |
| XX全貌 | XX概览 / XX总览 / XX四维度 | "全貌"过于宏大，人类很少这样写 |
| XX全景图 | XX总览 / XX架构总图 / XX矩阵 | 同上 |
| 全链路XX | 端到端XX / 从XX到XX | "全链路"是互联网黑话，正式文档避免 |
| Phase 0: 基础夯实 | Phase 0: 基础准备 / 工具就绪 | "夯实"是典型 AI 用词 |
| K8s 深度融合 | K8s 原生集成 / 与 K8s 紧密集成 | "深度融合"空洞 |
| 平台深度集成 | 平台原生对接 / 与平台紧密对接 | 同上 |
| 深度解析 | 详细分析 / 逐层拆解 | 如果出现的话 |
| 数据资产沉淀 | 数据积累 / 形成可复用的数据 | "沉淀"是互联网黑话 |
| 赋能 | 支持 / 帮助 / 为XX提供能力 | 过度使用的互联网黑话 |
| 抓手 | 切入点 / 手段 / 工具 | 同上 |
| 打通 | 对接 / 连通 / 集成 | 口语化且被滥用 |
| 闭环 | 完整流程 / 形成循环 / 端到端覆盖 | 视上下文决定，非一律禁止 |
| 底座 | 基础层 / 基座 / 底层支撑 | "底座"过于口语 |
| 拉齐/对齐 | 统一 / 保持一致 / 同步 | 互联网黑话 |
| 颗粒度 | 粒度 / 细度 / 精度 | "颗粒度"是冗余表达 |
| 心智 | 认知 / 理解 / 印象 | "用户心智"是营销黑话 |
| 势能 | 优势 / 影响力 / 积累 | 物理学词汇被滥用 |
| 链路 | 流程 / 路径 / 通路 | 非网络/通信语境下避免 |

## 二、句式层面的规避

| 规避模式 | 替代方向 | 说明 |
|----------|----------|------|
| "让我们来看一下..." | 直接陈述内容 | 过渡性废话 |
| "值得注意的是..." | 直接说要点 | AI 常用的"假客气" |
| "不难发现..." | 直接给结论 | 同上 |
| "本质上来说..." | 直接说结论，或用"核心是" | 过度使用 |
| "从XX维度来看" | 直接说内容，必要时用"在XX方面" | 维度被滥用 |
| "构建了XX的XX" | 简化为动宾结构 | AI 喜欢嵌套名词 |
| 连续三个以上排比句 | 减少到两个，或改用列表 | AI 倾向堆砌排比 |

---

## 三、使用原则

1. **语境优先**：同一个词在不同语境下可能合理（如技术文档中"链路追踪"是正式术语，不需要替换）
2. **不做机械替换**：规避的是"AI味"的表达习惯，不是禁止某个字出现
3. **保持专业性**：替换后的表达必须准确，不能为了避免AI味而损失专业含义
4. **简洁为上**：如果一个词可以删掉而不影响意思，直接删掉比替换更好
5. **读出来顺口**：最终检验标准——这句话像不像一个资深从业者写的

---

## 四、自查方法

写完文档后，检查以下信号：
- 同一段落中是否出现 3 个以上本表中的词汇 → 需要改写
- 是否有"大词小用"（用宏大词汇描述简单事情）→ 降级表达
- 是否有连续排比/对仗结构 → 打破对称，让句式更自然
- 删掉某个修饰词后意思是否不变 → 不变就删掉
