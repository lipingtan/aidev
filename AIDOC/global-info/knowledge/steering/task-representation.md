# 任务可执行表示规范

> 核心理念：每个制作任务必须有明确的输入、产出和验收标准。
> 本文件定义任务的标准格式，适用于所有功能开发、内容填充、迭代优化任务。

---

## 一、任务三要素

每个 Task 必须包含：

| 要素 | 定义 | 回答的问题 |
|------|------|-----------|
| **Scope（范围）** | 涉及哪些文件、系统、数据 | "改什么、不改什么" |
| **Constraints（约束）** | 必须遵循的规范和限制 | "怎么改、有什么红线" |
| **Acceptance（验收标准）** | 可逐条勾选的完成检查清单 | "怎么算做完了" |

---

## 二、复杂度分级

| 复杂度 | 典型场景 | 三要素要求 |
|--------|----------|-----------|
| **低** | 数据填充、参数调整、单文件修改、文档补充 | 只需 Acceptance |
| **中** | 新增组件/系统、实现单个子功能、新增数据表 | Scope + Acceptance |
| **高** | 多文件协作系统、跨系统集成、架构变更 | 完整三要素 |

---

## 三、任务格式示例

### 高复杂度

```markdown
### Task: 实现 Buff 系统

**复杂度**: 高

**Scope（范围）:**
- 创建文件: buff_data.gd, buff_list_component.gd, buff_tick_system.gd
- 涉及系统: StatsSystem（修改属性修饰器）、EventBus（发送 buff 事件）、ObjectPool（Buff 实例复用）
- 不触碰: 战斗系统的伤害计算逻辑（只提供接口供其调用）

**Constraints（约束）:**
- 继承框架基类（EcsComponent / EcsSystem）
- 单文件 ≤200 行
- 堆叠模式支持：stack / refresh / independent
- Buff 周期 tick 使用 delta 累加，不依赖 Timer 节点
- 所有参数有类型标注，注释使用中文

**Acceptance（验收标准）:**
- [ ] 3 个文件创建且语法无错误
- [ ] Buff 可添加/移除/查询
- [ ] 3 种堆叠模式行为正确
- [ ] 周期 tick 按 interval 触发效果
- [ ] 过期 Buff 自动移除并发送事件
- [ ] 属性修饰器在 Buff 添加/移除时正确增减
- [ ] 文件头注释包含依赖说明
```

### 中复杂度

```markdown
### Task: 实现经验值组件

**复杂度**: 中

**Scope:**
- 创建文件: experience_component.gd
- 涉及系统: EventBus（监听 enemy_killed）

**Acceptance:**
- [ ] 组件可挂载到 Entity
- [ ] add_exp() 正确累加经验值
- [ ] 达到阈值时发出 level_up_ready 信号
- [ ] 经验阈值按成长曲线公式计算
```

### 低复杂度

```markdown
### Task: 调整主角移动速度参数

**复杂度**: 低

**Acceptance:**
- [ ] move_speed 从 5.0 改为 6.5
- [ ] 加速时间从 0.2s 改为 0.15s
- [ ] 实际操作手感更灵敏
```

## 四、执行规则

### 执行前
1. 读取该任务的三要素
2. 确认 Scope 中引用的依赖文件/系统存在
3. 确认 Constraints 中引用的规范文件可访问

### 执行中
1. 严格在 Scope 范围内操作，不越界修改
2. 遵循 Constraints 中的所有约束
3. 代码遵循引擎代码生成规范

### 执行后
1. 逐条验证 Acceptance
2. 执行代码级 POST-CHECK（见 `execution-protocol.md` 第五节）
3. 全部通过才标记完成
4. 未通过项修复后重新验证

## 五、任务依赖表示

多个任务间的依赖用 DAG 表示：

```
T1 → T2 → T3
       ↘ T4 (可与 T3 并行)
```

规则：
- 无依赖的任务可并行执行
- 有依赖的任务必须等前置完成
- 循环依赖禁止（说明设计有问题，需重新拆解）
