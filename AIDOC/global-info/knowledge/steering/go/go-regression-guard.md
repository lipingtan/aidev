# Go 回归防护规范（Regression Guard）

> 核心理念：每次变更不仅要定义"做什么"，还要定义"不能破坏什么"。

---

## 一、为什么需要回归防护

AI 执行任务时，如果只关注"新增功能"而不明确"不能破坏什么"，容易出现：
- 修改公共中间件时影响其他模块
- 新增逻辑覆盖了已有的边界处理
- 接口签名变更导致前端调用报错
- 配置变更影响其他环境
- 租户隔离被意外破坏

---

## 二、适用范围

| 变更类型 | 是否需要回归防护 |
|----------|:---:|
| 跨模块变更 | ✅ 必须 |
| 单模块内变更 | ✅ 必须（可简化） |
| 小型修改（单文件） | ⚠️ 涉及公共组件时必须 |
| Bugfix | ✅ 已有（不变行为章节） |

---

## 三、在 design.md 中的体现

每个变更的 design.md 必须包含「不变行为清单」章节：

```markdown
## 不变行为清单（回归防护）

本次变更不应影响以下已有功能：

| 编号 | 不变行为 | 验证方式 | 涉及模块 |
|------|----------|----------|----------|
| RG-1 | 现有登录流程不受影响 | /login 接口正常返回 token | auth |
| RG-2 | 租户隔离不被破坏 | 不同 tenant_id 数据不互通 | game |
| RG-3 | 现有 API 接口签名向后兼容 | 旧版前端调用不报错 | 所有模块 |
| RG-4 | 安装向导流程不受影响 | 新安装能正常完成初始化 | setup |
```

### 编写规则

1. **格式**：`WHEN <已有场景> THEN 系统 SHALL CONTINUE TO <保持行为>`
2. **来源**：从以下维度检查是否有不变行为需要声明：
   - 本次修改的文件被其他模块引用
   - 本次修改的接口有前端或外部调用方
   - 本次修改的中间件影响所有路由
   - 本次修改的公共 Model 被多处使用
   - 本次修改可能影响租户隔离
3. **粒度**：每个不变行为对应一个可验证的检查点

---

## 四、在 tasks.md 中的体现

不变行为清单中的每一项，必须被分配到至少一个 Task 的 Acceptance 中：

```markdown
**Acceptance（验证标准）:**
- [ ] 新增接口正常返回数据
- [ ] go build ./... 零错误
- [ ] 【回归】现有登录接口不受影响（RG-1）
- [ ] 【回归】租户隔离正常工作（RG-2）
```

标注格式：`【回归】描述（RG-编号）`

---

## 五、Go 项目常见回归风险场景

| 变更类型 | 常见回归风险 | 防护措施 |
|----------|-------------|----------|
| 修改 `common/middleware/` | 所有路由的中间件链受影响 | 验证登录、权限、租户中间件正常 |
| 修改 `common/models/` | 所有嵌入该 Model 的表结构变化 | 验证 AutoMigrate 不报错 |
| 修改 `handler/auth.go` | JWT payload 变化，前端解析失败 | 验证前端登录和 token 使用正常 |
| 修改 `setup.go` | 安装流程异常 | 验证全新安装能正常完成 |
| 修改路由注册 | 路由冲突或缺失 | 验证所有已有接口可访问 |
| 修改 `embed.go` 或前端产物 | 静态文件服务异常 | 验证前端页面正常加载 |
| 修改 `db.sql` | 初始化数据异常 | 验证全新安装后能正常登录 |
| 新增全局中间件 | 现有请求链路被拦截 | 验证所有接口响应正常 |

## 六、回归防护检查清单

### design.md 生成时

- [ ] 是否列出了所有可能受影响的已有功能
- [ ] 每个不变行为是否有明确的验证方式
- [ ] 是否覆盖了跨模块影响
- [ ] 是否考虑了租户隔离的影响

### tasks.md 生成时

- [ ] 每个 RG 项是否被分配到至少一个 Task 的 Acceptance 中
- [ ] 高复杂度任务是否在 Constraints 中引用了相关 RG 项

### Task 执行后

- [ ] 所有标注【回归】的 Acceptance 项是否验证通过
- [ ] `go build ./...` 零错误
- [ ] `go vet ./...` 无警告
- [ ] 如果无法自动验证，是否标注"需人工确认"

---

## 七、与 Bugfix 三段式的关系

Bugfix 的三段式已包含回归防护：

```
当前行为（缺陷）：WHEN ... THEN 系统 <错误表现>
期望行为（正确）：WHEN ... THEN 系统 SHALL <正确行为>
不变行为（回归）：WHEN ... THEN 系统 SHALL CONTINUE TO <保持行为>
```

本规范将第三段的思想推广到所有变更的 design.md 中。
