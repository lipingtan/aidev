# CR15 套餐购买限购与限时优惠 — 需求

> 状态：一期（购买限购）已实现（feature 分支，2026-11-22）；二期（限时优惠）设计已确认、待编码。
> 来源：用户 2026-11-22 口述需求，设计确认记录见下。

## 1. 背景

套餐定价（`price_configs`）目前只有"上架/下架"人工开关与价格，缺两类经营能力：

1. 限量售卖：一个套餐总共只卖 N 份，卖完自动下架（可改上限恢复）；
2. 新客/限量策略：每个用户最多买 N 次（典型 N=1，首购特惠不可重复薅）；
3. 限时促销：App 端对全体/指定用户限时改价的运营机制（二期）。

## 2. 需求点

| # | 需求 | 期数 |
|---|---|---|
| R1 | 每个套餐定价可设**总购买上限**；超限自动"售罄"不可再购；**改上限即恢复销售**（无需重新上架动作） | 一期 ✅ |
| R2 | 每个套餐定价可设**单用户购买上限**（如 1 次）；某用户购满后不能再购该套餐；上限可改 | 一期 ✅ |
| R3 | 对 App 用户的**限时优惠购买机制**（限时改价 + 倒计时 + 防改包） | 二期 |

## 3. 已确认的设计决策（用户 2026-11-22 拍板）

| 决策点 | 结论 |
|---|---|
| 不限的表示法 | **`-1` 显式不限**（数据库非空列 `DEFAULT -1`，不用 NULL 三态）；`0` 禁止录入（防手滑瞬间击杀，停售走"下架"开关） |
| pending 未付订单**占名额** | 是——下单即锁名额，30 分钟超时关闭自动释放 |
| 单人限购口径 | 按账号 `user_id` 计（匿名未登录本就无法购买） |
| 管理端售罄后**行内一键改上限** | 要——列表"改限购"弹窗直接改，改大即恢复可售 |
| 促销立项 | 新建 CR15 承载（本文档），二期编码 |
| 分支纪律 | 本 CR 代码只在 feature 分支开发测试，用户测过再合 main |

## 4. 验收口径

- 设总上限 N：第 N+1 次下单被拒（文案"已被抢光"），量不够时提示"仅剩 X 份"；
- 改大上限（-1 或更大值）：立即恢复可购，无需任何"上架"操作；
- 设每人 1 次：同一账号第二次下单被拒（文案"每人限购 1 次，您已购 1 次"），换账号可买；
- 退款/超时关闭的订单自动回补名额；
- 老版本 App 未升级：购买链路照常（拦截在服务端，错误文案直接透传 Toast），公开列表新增字段为增量不影响解析。
