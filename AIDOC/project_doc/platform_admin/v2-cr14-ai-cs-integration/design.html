2数据模型变更

CsAgent — 新增 agent_type 字段

// models.go — CsAgent 追加字段
type CsAgent struct {
    // ... 现有字段不变 ...
    AgentType string `gorm:"type:varchar(20);not null;default:'human'" json:"agent_type"`
    // 值："human"（默认）| "bot"
    // bot 类型的 CsAgent 对应 agent_bot 管理端账号
    // 管理端工作台列表展示时带 🤖 标识，不计入人工客服在线数

  • 新建会话时，自动将 session.agent_id 设为 bot 类型的 CsAgent ID（表示「bot 正在处理」）
  • 转人工时，将 session.agent_id 换为人工客服 ID，mode 改为 human
  • 管理端工作台会话列表：可清楚区分「bot 处理中」/ 「人工处理中」/ 「未分配」三种状态

CsSession — mode 状态流转

新会话创建 mode = "bot", agent_id = <bot CsAgent ID> │ │ 触发转人工（任意策略） ▼ mode = "human", agent_id = <人工客服 CsAgent ID 或 NULL> │ │ 管理端手动切回 bot（AdminSetSessionMode） ▼ mode = "bot", agent_id = <bot CsAgent ID>

// models.go — 新增 CsMute 表
type CsMute struct {
    ID         int64      `gorm:"primaryKey;autoIncrement" json:"id"`
    TenantID   int64      `gorm:"not null;uniqueIndex:uk_cs_mute_user" json:"tenant_id"`

登录 URL、刷新 URL、请求报文模板全部在 go-rag-agent 管理页面配置，不写死代码，支持适配不同系统的登录接口。

TokenManager 行为

  • 启动时不立即登录（懒初始化），第一次工具调用时触发登录
  • 后台 goroutine 定时检查，提前 advance_refresh_secs 秒自动刷新
  • 刷新失败时重试 3 次，全失败则重新登录
  • 管理页面保存新配置后，下次 token 操作时热更新生效
  • token 通过 callctx 注入每次 MCP 工具调用的 Authorization: Bearer header

5转人工触发策略（可配置）

四种触发策略全部支持，触发规则（轮次数 N、关键词列表）在 go-rag-agent 管理页面配置，不写死代码。

策略清单

策略触发条件配置项执行路径
策略1：用户主动指令 用户说「转人工」「联系客服」「要人工」等 语义识别（LLM 判断意图），无额外配置 Agent → handoff_to_human MCP 工具
策略2：Agent 无法回答 RAG 召回为空 + LLM 判断超出能力范围 handoff.no_answer_msg（告知等待文案，可配）
handoff.no_human_msg（无人工可用文案，可配） 		① Agent 先调 send_bot_message 发出等待提示（如「您的问题需要人工处理，正在为您转接，请稍候」）
② 再调 handoff_to_human
③ platform_admin 侧：HandoffToHuman 检查是否有在线人工客服（cs_agents 中 is_online=true AND agent_type=human 的数量）
  - 有在线人工 → 正常排队，mode 变 human
  - 无在线人工 → mode 仍变 human（保留排队），但额外插入一条 bot 系统消息告知用户：「当前人工客服暂时不在线，您的问题已记录，客服上线后将第一时间回复您」（文案可配 handoff.no_human_msg）
策略3：超轮次自动转人工 同一 session 内用户消息数 ≥ N 且 mode 仍为 bot handoff.max_bot_turns（默认 10，0=不限） platform_admin AgentService 在触发 AI 前检查轮次，满足则直接调 HandoffToHuman
策略4：关键词触发 消息内容命中关键词列表 handoff.keywords（逗号分隔，如 投诉,退款失败,骗人,举报） platform_admin AgentService 在存消息后、触发 AI 前做关键词匹配，命中则直接转人工
管理员手动接管 管理端工作台点「接管」按钮 无配置，已有 AdminHandoffToHuman 接口 管理端直接调现有接口

此区块控制是否启用 AI 客服机器人。默认关闭，关闭时 platform_admin 完全不感知机器人存在——新会话直接进人工队列，UserSendCsMessage 不触发 AI，前端不显示任何 bot 相关状态。

6禁言功能

管理端客服可以对指定用户设置禁言时长（或永久禁言）。用户被禁言后发消息会收到禁言提示，不会进入消息队列。

接口设计

接口方法说明
/admin/cs/sessions/:id/mute POST 对该会话的用户设置禁言。body: { duration_hours: 1.5, reason: "..." }，以小时为单位，支持 1 位小数（如 0.5=30分钟，1.5=90分钟）；duration_hours=0 表示永久禁言
/admin/cs/sessions/:id/unmute POST 解除该会话用户的禁言
/admin/cs/mutes GET 查询当前租户所有禁言列表（分页），可按 user_id / 是否有效过滤

前端 UI 时长选项：0.5h / 1h / 2h / 6h / 12h / 24h / 72h / 永久，也支持自定义输入（精度 0.1h）。换算：mute_until = now + duration_hours × 3600s，存储为 UTC 时间戳。

禁言检查逻辑

// UserSendCsMessage 最开头追加
func (h *LicenseHandler) UserSendCsMessage(c *gin.Context) {
    authCtx := middleware.GetAuthContext(c)
    tenantID, userID := authCtx.TenantID, authCtx.UserID

    // ① 禁言检查（优先，在存消息之前）
    muted, muteUntil, err := h.csSvc.CheckMuted(tenantID, userID)
    if err == nil && muted {
        msg := "您已被禁言"
        if muteUntil != nil {
            msg = fmt.Sprintf("您已被禁言，禁言将于 %s 结束", muteUntil.Format("2006-01-02 15:04"))
        } else {
            msg = "您已被永久禁言，如有疑问请联系平台"
        }
        c.JSON(http.StatusForbidden, gin.H{"code": 403, "msg": msg,
            "mute_until": muteUntil})
        return
    }
    // ... 后续正常逻辑
}

方案：多轮流（业界标准，OpenAI / Claude / Gemini 同款）

每轮 LLM 生成都流式推送，工具调用期间推送状态事件，工具返回后新一轮流式生成最终回答：

第1轮流： LLM 流式输出 tokens → 前端实时渲染 遇到工具调用 → 推送 tool_start 事件（desc: "正在执行：<工具名>..."） 工具执行（同步阻塞，MCP 调用） 工具完成 → 推送 tool_end 事件 ↓ 第2轮流：把工具结果喂给 LLM，再次流式输出最终回答 ↓ 循环直到无工具调用 → 推送 [DONE]

SSE 事件格式

事件类型数据示例说明
meta{"type":"meta","content":"{\"rag_docs\":4,\"rag_score\":0.734,\"strategy\":\"rag_answer\"}"}RAG 检索完成后推送，含命中条数、最高相似度、决策策略（rag_answer / tool_answer / rag_assisted / refuse）；前端展示在思考区块 header
thinking{"type":"thinking","content":"Let me check..."}LLM reasoning_content delta（模型开启推理时产生），前端实时追加到思考区块
token{"type":"token","content":"你好"}LLM token 片段，前端追加渲染正文
tool_start{"type":"tool_start","tool":"query_member_info","desc":"正在执行：query_member_info..."}工具开始，前端显示加载动画
tool_end{"type":"tool_end","tool":"query_member_info"}工具完成，前端清除加载
donedata: [DONE]流结束
error{"type":"error","message":"..."}错误事件
