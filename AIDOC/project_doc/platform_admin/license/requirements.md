# License 插件 - 需求文档

## 项目背景
为 mjarch flavor 的 PhoenixUI Android App 提供会员制激活服务。与现有激活制 flavor（mjguoguan1、tcb1 等）不同，mjarch 采用类似会员订阅的机制，支持有效期、多设备同步和激活码顺延。

> **重要约束**：本文档描述的新激活机制**仅用于 mjarch flavor**。其他所有 flavor（mjguoguan1、tcb1、jdgamespace 等）保持原有旧激活机制（ActivationAccessControl + 旧 PHP 后端）不变，不在本文档范围内，也不允许受到本次改动影响。

## 用户故事

### US-01: 用户登录
**As a** 用户
**I want to** 使用手机号和短信验证码登录
**So that** 我可以在设备上恢复我的会员身份

### US-02: 用户注册
**As a** 新用户
**I want to** 使用手机号注册账号
**So that** 我可以创建会员身份并开始使用服务

> 注册流程复用 platform_admin user_auth 模块（手机号+验证码）。登录即注册：用户首次使用手机号+验证码登录时，系统自动创建账号。

### US-03: 激活会员
**As a** 已登录用户
**I want to** 输入激活码激活会员身份
**So that** 我可以访问会员专属内容

### US-04: 多设备同步
**As a** 已登录用户
**I want to** 在最多2台设备上登录并自动同步会员状态
**So that** 我可以在不同设备间无缝切换

### US-05: 会员到期顺延
**As a** 会员用户
**I want to** 使用新的激活码时从当前剩余时间基础上顺延
**So that** 我不会损失已购买的会员时间

### US-06: 激活码恢复
**As a** 会员用户
**I want to** 在会员过期后使用之前的激活码恢复会员身份
**So that** 我可以在需要时重新激活

## 功能需求

### FR-01: 用户管理（复用 platform_admin user_auth 模块）
- FR-01.0: 注册流程复用 user_auth 模块的 `/send-code` + `/login` 接口（登录即注册，首次使用手机号登录时自动创建账号）
- FR-01.1: 支持手机号+短信验证码登录（复用）
- FR-01.2: 支持退出登录（复用）
- FR-01.3: 支持管理登录设备（查看、踢出）（license 插件新增）

### FR-02: 激活码管理
- FR-02.1: 激活码包含激活时长（天）和会员等级
- FR-02.2: 每个激活码只能被一个用户使用一次
- FR-02.3: 激活码激活后记录使用时间和使用者
- FR-02.4: 激活码支持自身过期时间（可选）
- FR-02.5: 支持创建激活码（管理端操作），指定会员等级和激活时长
- FR-02.6: 激活码有类型定义（模板），不同类型的激活码可以有不同的逻辑和默认属性
- FR-02.7: 激活码实例可以覆盖类型定义中的某些属性，默认继承类型定义
- FR-02.8: 激活码实例（activation_codes）和激活记录（activation_records）分开刻画

### FR-03: 会员管理
- FR-03.1: 支持多种会员等级（普通会员、VIP、至尊）
- FR-03.2: 会员有有效期，过期后自动失效
- FR-03.3: 同一用户使用新激活码时，从当前剩余时间基础上顺延
- FR-03.4: 支持激活码恢复（使用之前用过的激活码恢复会员身份）
- FR-03.5: 用户可以查看自己的激活记录列表
- FR-03.6: 会员身份可叠加（用户可同时拥有多个会员类型，每个会员类型独立计算过期时间）
- FR-03.7: 支持取消激活码（管理端操作），取消后该激活码贡献的会员时间从用户总会员时间中减去。此操作仅限管理端在欺诈/误操作处理场景使用，执行后应通知用户；用户侧无此入口。

### FR-04: 多设备支持
- FR-04.1: 同一用户最多可在 N 台设备上登录，N 由服务端配置项 `license.max_devices` 控制，默认为 2
- FR-04.2: 登录时自动同步该用户的会员状态到当前设备
- FR-04.3: 支持踢出指定设备

### FR-05: 客户端集成
- FR-05.1: **mjarch flavor 专用**：使用新的会员制激活逻辑（MembershipAccessControl），仅在 mjarch flavor 中启用
- FR-05.2: **其他 flavor 不变**：mjguoguan1、tcb1、jdgamespace 等所有其他 flavor 保持原有旧激活机制（ActivationAccessControl + 旧 PHP 后端），本次改动不得触及这些 flavor 的任何代码和配置
- FR-05.3: 客户端本地缓存会员状态，支持离线检查

### FR-06: 到期提醒
- FR-06.1: 会员有效期剩余 ≤ 7 天时，客户端启动时展示提醒 Toast
- FR-06.2: 服务端 `/status` 接口在响应中新增 `warning_days_left` 字段：剩余天数 ≤ 7 时返回具体剩余天数，否则返回 `null`

## 非功能需求

### NFR-01: 安全性
- API 使用 JWT token 认证
- 本插件（license）的客户端与服务器之间的通信使用 RSA 加密（RSA/ECB/PKCS1Padding，**2048位**），使用独立密钥对，与其他 flavor 的旧激活机制密钥完全隔离，互不影响
- 激活码使用随机字符串，难以猜测

### NFR-02: 可扩展性
- 会员等级可配置，支持后续新增等级
- 激活码批量生成工具

### NFR-03: 兼容性
- 与现有 platform_admin 架构兼容（插件化部署）
- 与现有 PhoenixUI App 架构兼容（FlavorFactory 模式）

## 验收标准

### AC-01: 登录
- [ ] 用户可以使用手机号+验证码登录
- [ ] 错误验证码登录失败

### AC-02: 激活流程
- [ ] 用户可以使用有效激活码激活会员
- [ ] 已使用的激活码不能被再次使用
- [ ] 激活成功后返回会员等级和过期时间

### AC-03: 顺延逻辑
- [ ] 同一用户使用新激活码时，过期时间 = max(当前时间, 原过期时间) + 激活码时长
- [ ] 不同用户使用同一激活码失败

### AC-04: 多设备
- [ ] 同一用户可以在 N 台设备上登录（N 由 license.max_devices 配置，默认 2）
- [ ] 超出设备数量限制时提示踢出已有设备
- [ ] 踢出设备后该设备无法访问

### AC-05: 客户端集成与隔离
- [ ] mjarch flavor 使用新的会员制激活（MembershipAccessControl）
- [ ] 其他 flavor（mjguoguan1、tcb1、jdgamespace 等）激活逻辑不受影响，仍走原有 ActivationAccessControl + 旧 PHP 后端
- [ ] mjarch 新激活使用独立 RSA 密钥（`license_rsa_key`），不复用旧激活机制的 `key1`
- [ ] 旧 PHP 后端无需任何改动，其密钥和接口与 license 插件完全独立
- [ ] 在 mjarch 上安装新版 APK 后，mjguoguan1 / tcb1 等其他 flavor 的激活功能测试通过（回归验证）
- [ ] 旧激活逻辑使用的 RSA 公钥（`key1`）在 mjarch flavor 中不应被加载或使用

### AC-06: 到期提醒
- [ ] 会员剩余 ≤ 7 天时，/status 接口返回 warning_days_left 字段（具体剩余天数）
- [ ] 会员剩余 > 7 天时，/status 接口返回 warning_days_left: null
- [ ] 客户端收到 warning_days_left 非 null 时，启动时展示提醒 Toast
