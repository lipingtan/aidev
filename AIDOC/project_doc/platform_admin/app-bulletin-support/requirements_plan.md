# CR 需求计划 — App 公告与客服支持

> 日期：2026-10-03
> 状态：**需求记录阶段（等待确认）**
> 来源：用户口头需求（2 个 TODO 合并为一个 CR 模块）

## 背景

App（mjarch flavor）需要补充两类面向 C 端用户的基础运营能力：

1. **公告信息展示**：运营在管理端发布公告，App 端展示给用户
2. **客服服务**：用户（含匿名）可向客服发消息，管理端可查看会话并回复；管理端需要消息推送提醒

## 需求一：公告信息展示

### 管理端
- 现状调研结论：**`bulletin` 插件已具备完整公告管理能力**（app/bulletin：模型/CRUD/管理端菜单/权限），无需重建
- 复用现有能力，本 CR 仅做适配性工作

### App 端（新增）
- App 首页搜索栏下方增加**公告信息模块**
  - 默认展示**最新一条已发布公告**（标题 + 摘要/内容）
  - 「更多」入口进入公告列表页，可查看以往公告（分页）
- 数据来源：公开接口 `GET /api/v1/user/public/bulletin/bulletins`（bulletin 插件已提供，匿名可访问）
- App 端需新增：公告模块 UI（首页横条/卡片）+ 公告列表页 + 公告详情展示

## 需求二：客服服务模块

### App 端（新增）
- 用户可发消息给客服，**支持匿名用户**（未登录也可发起，本地生成匿名会话标识）
- 聊天界面：消息列表 + 输入框，可查看客服回复（轮询或进入时刷新）

### 后端（新增）
- 会话/消息数据模型：
  - 会话表：session_id、tenant_id、user_id（可空=匿名）、匿名标识（device_id）、状态（进行中/已结束）、最近消息时间
  - 消息表：会话外键、发送方（用户/客服）、内容、发送时间、已读标记
- 接口：
  - 用户端：创建/获取会话、发送消息、拉取消息（增量）
  - 管理端：会话列表（含匿名标记）、会话消息详情、客服回复

### Web Admin 端（新增）
- 新增「客服会话管理」页面：会话列表（用户标识/最后消息/未读数/状态）→ 进入查看对话记录并回复

### 消息推送（PWA Web Push）
- Web Admin 端以 PWA 安装后，**用户发送新消息时管理端收到推送提醒**
- 技术路线：Web Push（VAPID）——管理端 Service Worker 注册订阅，订阅信息存服务端；用户消息落库后服务端向所有有效订阅推送提醒
- 管理端需要：PWA manifest + Service Worker + 推送订阅开关（浏览器权限）

## 待确认问题（需求阶段）

1. 公告模块是否需要支持「置顶/有效期内才显示」？（建议本期：按发布时间倒序取最新，不做置顶）
2. 客服匿名用户：会话绑定 device_id，同一设备后续打开视为同一会话继续聊——是否符合预期？
3. 客服回复是否需要推送到 App 端（本期 App 仅轮询拉取，App 推送需接入厂商通道，工作量大，建议本期不做）？
4. PWA 推送的目标：仅推给管理端登录的管理员？（是——用户消息提醒管理员）

## 范围外（明确不做）

- App 厂商推送通道（小米/华为/FCM）——客服回复的 App 端推送
- 公告富文本编辑器（本期纯文本）
- 多客服坐席/会话分配
