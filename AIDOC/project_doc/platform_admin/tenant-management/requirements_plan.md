# 需求计划：租户管理体系

## 目标

为 SaaS 底座设计完整的多租户管理体系，支持游戏开发创作者自助注册、管理自己的团队和资源。

## 澄清问题

### 一、租户模型

[Question] 租户的定义是什么？
- 方案 A：一个租户 = 一个游戏工作室/公司（下面有多个用户）
- 方案 B：一个租户 = 一个独立开发者（单人）
- 方案 C：两者都支持（个人开发者和团队都可以注册）

[Answer]
方案A
[Question] 租户之间的数据隔离级别？
- 方案 A：共享数据库 + tenant_id 字段隔离（当前方案）
- 方案 B：每个租户独立数据库（完全隔离，成本高）
- 方案 C：先用 A，后续大客户可升级为 B

[Answer]
方案C
### 二、注册与开通

[Question] 租户注册方式？
- 方案 A：自助注册（填写信息 → 邮箱验证 → 立即可用）
- 方案 B：申请制（填写信息 → 管理员审核 → 开通）
- 方案 C：自助注册 + 可选人工审核（免费版自动开通，付费版需审核）

[Answer]
方案C
[Question] 注册时需要收集哪些信息？
- 基础：邮箱、密码、昵称
- 扩展：公司名称、联系电话、团队规模
- 实名：营业执照、身份证（合规需要时）

[Answer]
这几项按需让用户提供，实名在注册后后面可以按需要再补充
[Question] 是否需要邮箱/手机验证？

[Answer]
需要邮箱验证
### 三、租户内用户管理

[Question] 每个租户内的用户角色体系？
- 方案 A：固定角色（租户管理员 + 普通成员）
- 方案 B：自定义角色（租户管理员可自行创建角色和分配权限）
- 方案 C：预设角色 + 可自定义（预设：管理员/开发者/运营/只读）

[Answer]
方案C
[Question] 租户管理员如何邀请成员加入？
- 方案 A：邀请链接（生成链接发给对方注册）
- 方案 B：邮箱邀请（输入邮箱发送邀请邮件）
- 方案 C：直接创建账号（管理员填写信息创建子账号）

[Answer]
方案A
### 四、配额与限制

[Question] 是否需要对租户做资源配额限制？
- 游戏数量上限
- DLC 数量上限
- 存储空间上限
- API 调用频率限制
- 用户数量上限

[Answer]
免费用户和付费用户需要区分资源配额
[Question] 是否需要套餐/计费体系？（免费版/基础版/专业版）

[Answer]
需要
### 五、超级管理员

[Question] 超级管理员（平台运营方）需要哪些管理能力？
- 查看所有租户列表
- 启用/禁用租户
- 调整租户配额
- 查看租户使用统计
- 代登录租户后台

[Answer]
需要
### 六、技术实现

[Question] 租户管理功能放在哪里？
- 方案 A：作为 Host 底座的核心功能（不插件化）
- 方案 B：作为插件实现
- 方案 C：超级管理员功能在 Host，租户自助功能作为插件

[Answer]
方案C
[Question] 租户注册页面是独立的公开页面还是集成在现有登录页？

[Answer]
独立公开页
