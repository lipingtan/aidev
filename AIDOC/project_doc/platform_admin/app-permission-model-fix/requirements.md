# 需求：应用-权限归属模型修正

## 背景

当前系统中菜单（admin_resource）和 API 权限（admin_api_permission）的归属关系不清晰。虽然数据表中有 `app_code` 字段，但界面上没有体现"菜单/API 归属于应用"的两层模型：
- 第一层（元配置）：应用定义自己拥有哪些菜单和 API
- 第二层（授权）：角色在某个应用范围内被分配哪些菜单和 API

需要修正模型表达和界面交互，使两层关系清晰可管理。

## 用户故事

- 作为平台管理员，我希望在应用管理界面中配置每个应用拥有的菜单和 API，以便统一管理应用能力定义
- 作为租户管理员，我希望在角色权限分配时按应用分组设置菜单/API 权限，只能看到本租户已订阅的应用
- 作为平台管理员，我希望能管理所有应用的权限配置，不受租户订阅限制

## 功能需求

### FR-1: 应用管理界面增加菜单/API 元配置管理

**描述：** 应用管理页面改为左右布局——左侧应用列表，选中一个应用后，右侧展示该应用的菜单管理 Tab 和 API 权限管理 Tab（类似角色管理页面的布局模式）。

**验收标准：**
- WHEN 平台管理员点击应用列表中某个应用 THEN 系统 SHALL 在右侧展示该应用的菜单树和 API 权限树
- WHEN 管理员在右侧菜单 Tab 新增/编辑/删除菜单 THEN 系统 SHALL 自动设置该菜单的 `app_code` 为当前选中应用的编码
- WHEN 管理员在右侧 API Tab 新增/编辑/删除 API 权限 THEN 系统 SHALL 自动设置 `app_code`

### FR-2: 角色权限分配按应用分组

**描述：** 角色详情页的"菜单权限"和"API 权限"Tab 中，增加应用选择器。选中应用后只展示该应用下的菜单/API 树。

**验收标准：**
- WHEN 租户管理员打开角色菜单权限 Tab THEN 系统 SHALL 展示该租户已订阅的应用下拉列表
- WHEN 选中一个应用 THEN 系统 SHALL 只展示 `app_code` 等于所选应用编码的菜单树
- WHEN 平台管理员打开角色菜单权限 Tab THEN 系统 SHALL 展示所有应用的下拉列表（不受租户订阅限制）
- WHEN 保存菜单权限 THEN 系统 SHALL 只保存当前所选应用范围内的勾选项

### FR-3: GetUserMenu 按用户角色绑定的应用过滤

**描述：** 用户菜单接口返回结果需按用户角色已绑定的应用范围过滤，用户只能看到自己角色绑定的应用下的菜单。

**验收标准：**
- WHEN 用户请求 user-menu THEN 系统 SHALL 只返回用户角色已绑定应用对应的菜单
- WHEN SUPER_ADMIN 请求 user-menu THEN 系统 SHALL 返回所有应用的菜单（现有行为不变）

### FR-4: 菜单/API 权限全局定义，租户共享

**描述：** 菜单和 API 权限是应用级的全局定义（`tenant_id=0` 或不隔离），所有订阅该应用的租户共享同一套定义。角色分配时引用全局定义的 ID。

**验收标准：**
- WHEN 平台管理员在应用下创建菜单 THEN 该菜单 `tenant_id` SHALL 为 0（全局）
- WHEN 任何租户的角色分配菜单权限 THEN 系统 SHALL 展示 `tenant_id=0` 且 `app_code` 匹配的全局菜单树

### FR-5: 隐藏独立菜单管理入口（待定）

**描述：** 独立的"菜单管理"页面暂时从侧边栏隐藏（功能冗余，菜单配置统一在应用管理中完成）。保留代码不删除，后续根据需要恢复。

**验收标准：**
- WHEN 用户查看侧边栏 THEN 系统 SHALL 不显示独立的"菜单管理"菜单项
- WHEN 直接访问 /system/menus 路径 THEN 页面仍可访问（路由不删除，只隐藏菜单）

## 非功能需求

- 向后兼容：现有 `tenant_id != 0` 的菜单数据需迁移为 `tenant_id=0`（或提供迁移脚本）
- seed 数据：初始化时菜单改为 `tenant_id=0`，绑定 `app_code="admin"`

## 影响范围

**数据模型改动：**
- `admin_resource.tenant_id` 元配置场景改为 0
- `admin_api_permission.tenant_id` 元配置场景改为 0
- 角色分配逻辑不变（`admin_role_resource` 直接引用资源 ID）

**后端改动：**
- `GetUserMenu` 查询条件修正：查全局菜单（`tenant_id=0`）+ 按 `app_code` 过滤
- `GetTree` 查询条件修正：按 `app_code` + `tenant_id=0` 过滤
- 角色权限分配接口无需改（已是直接绑 ID）
- seed 数据 `tenant_id` 改为 0

**前端改动：**
- 应用管理页面改为左右布局 + 菜单/API Tab
- 角色菜单权限 Tab / API 权限 Tab 加应用选择器
- 隐藏独立菜单管理侧边栏入口
- `getResourceTree` 接口调用时传 `app_code` 参数
