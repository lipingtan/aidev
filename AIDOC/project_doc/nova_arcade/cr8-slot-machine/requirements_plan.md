## 需求理解

**目标**：新增第 5 款游戏——方形轮盘押注机：正方形面板边缘一圈图标位循环滚动，玩家在底部对**单个或多个符号**分别押注币数，开评委运气结算，验证「多注落下注」型游戏的接入。

**玩法形态**（对齐用户描述）：
- **面板**：正方形，边缘均匀分布 N 个符号位（N=12 推荐，可 8~16），中央显示结果/余额/提示；符号用 ThemeTokens 配色自绘（Label/ColorRect，无外部素材）
- **滚动**：点「旋转」后整圈图标循环位移，缓出减速停在随机位（Tween 演出 ~2.5s，结果先抽后演）
- **押注区**（面板底部）：一排符号押注位（每种符号一个），点选符号 + 选注额（1/5/10）可多符号多注；「旋转」时所有押注生效
- **结算**：指针停在符号 S → 押中 S 的注按赔率赔付（多倍返还），未中没收；支持「连环奖」（连续停在同名符号翻倍赔率，可选，见 Q4）

**范围**：
1. 新建 `games/slot_machine/`（gid 不变，形态改为轮盘）：meta.json + module.tscn + module_adapter.gd + src/ + icon.png（snake 模板结构）
2. src 单文件 ≤380 行级（snake 336 行参照）：面板布局、滚动动画、押注状态机、赔付表、余额账本
3. 虚拟币账本：余额存 `ctx.save_dir/save.cfg`（每局结算强写），初始 100，破产救济（见 Q3）
4. 结算卡对接：quit_requested({score=会话累计净变化, playtime, achievements[], extra:{balance, biggest_win, streak_symbol, streak_count}})；GameModule 协议零改动（评审后修订：见 requirements.md FR-6.1）
5. 成就 ×2（首次押中最高赔率符号 / 单局 win ≥300），经 quit achievements 批量交付（评审后修订：见 requirements.md FR-7.2）
6. editorial.json banner 追加 1 条
7. 测试：headless 套件含万局统计断言 + GUI 截图取证（双主题 × 押注/滚动/中奖/破产四态）

**不在范围**：
- 真实支付/充值（M4）；币不可购不可提
- 联网对战/榜内奖池联动；多面板多指针
- 横屏布局；Shell 改动

## 假设列表

- [假设-1] 12 符号位、6 种符号各出现 2 次（对称分布），滚动为整圈位移+相位停准（等价于 12 面骰），概率=均匀 1/12 按符号聚合。
- [假设-2] 押注交互：底部押注位按一下+1 注（重复点击叠加），长按清零该符号（或右键/双击清零——GUI 探针阶段定，不新增 UI 元素）。
- [假设-3] 滚动期间锁定押注区与旋转按钮（防连点竞态，沿用回菜单 FOCUS_NONE 教训）。
- [假设-4] 赔付表静态 const Dictionary，test 与 src 共享同一常量文件防漂移。

## 澄清问题

- [Question-1] 面板符号构成与赔率（决定 RTP 的核心参数）？
  - 业界最佳实践：轮盘类 hit rate 与赔率联动——赔率高→出现次数少。娱乐向定位 RTP 95%~105% + 高频小奖。
  - 推荐答案及理由：**6 种符号 × 各 2 位 = 12 位；赔率梯度 樱桃×3 / 柠檬×4 / 铃铛×6 / 星×8 / 钻石×12 / 七×24**。数学：均匀 1/12 命中，期望回报 = Σ(2/12 × 赔率) = (3+4+6+8+12+24)/6 = **9.5 → RTP≈79%**，偏低——把七的赔率提到 ×24 是为爽感，但会拉低整体 RTP；**修正推荐：樱桃×5 / 柠檬×6 / 铃铛×8 / 星×10 / 钻石×14 / 七×20 → (5+6+8+10+14+20)/6 ≈ 10.5 → RTP≈88%**，仍偏保守但留出「连环奖/多注分散」的加成空间到 ~95%。具体数值在 design 阶段按命中分布微调锁定。
  [Answer-1] 采纳推荐：6 符号×2 位，赔率 5/6/8/10/14/20，RTP≈88%（design 阶段可 ±3% 微调）（2026-08-31 确认）
- [Question-2] price_model 与押币关系？
  - 推荐答案及理由：**free + 虚拟币纯赠送**（初始 100、救济免费），币不可购不可提，无赌博合规风险；trial 不叠加。
  [Answer-2] 采纳推荐：free + 虚拟币纯赠送（2026-08-31 确认）
- [Question-3] 破产救济形态？
  - 推荐答案及理由：**余额 < 1 时弹「领取救济 50」按钮，无冷却无上限**。
  [Answer-3] 采纳推荐：余额<1 弹救济 50，无冷却无上限（2026-08-31 确认）
- [Question-4] 连环奖（streak bonus）要不要？
  - 业界最佳实践：街机轮盘（如 Rose Roulette）常见「连续停同符号赔率翻倍」制造高潮，但增加状态复杂度（需记录上一局结果）。
  - 推荐答案及理由：~~V1 不做~~ → **用户确认要做（2026-08-31）**：上一局与当前局停在同名符号 → 本次押中该符号的赔付翻倍（×2）；UI 在中央提示「连击！×2」；streak 状态记入内存与 extra（{streak_symbol, streak_count}），不落盘（会话内有效）。理由：制造高潮点；复杂度可控（一个状态字段+一条赔付分支）。
  [Answer-4] 采纳用户决定：做连环奖，同符号连停押中赔率×2，streak 会话内有效（2026-08-31 确认）
- [Question-5] 结算卡 score 语义 + 万局统计断言口径？
  - 推荐答案及理由：**score = 本局净变化（可负），best 取 max**；统计断言跑 10000 局：单符号实测频率 ∈ [1/12 ± 2%]、基础 RTP ∈ [85%, 92%]、含连环奖加成后上限放宽至 95%、每符号均有命中。GUI 四态截图双主题。
  [Answer-5] 采纳推荐：score=本局净变化，万局统计断言（2026-08-31 确认）
