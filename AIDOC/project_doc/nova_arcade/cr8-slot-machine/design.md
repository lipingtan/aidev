## 3. LUCKY 散花机制（v2 新增核心）

- **触发位置语义**（用户描述）：跑灯经过**大 LUCKY 左侧一格（格 20）**→ 触发大 Lucky 散花；经过**小 LUCKY 右侧一格（格 10）**→ 触发小 Lucky 散花
- **散花表现**：从触发格向盘面中央散出多个光点灯：
  - 大 LUCKY：5~7 个灯
  - 小 LUCKY：3~4 个灯
  - 散出数量 = rng.randi_range(5,7) / (3,4)
  - 一次全散 或 逐个散（间隔 0.15s 逐个弹出）——**实现取逐个散**（观感更好，与用户「可以一个一个灯散出来」一致）
- **散花结算**：散出的每个灯随机落在盘面符号上（按格数权重抽取），**每个散灯按其落点符号 ×2 赔付押中该符号的注**（未押不赔）。散灯落点展示为盘面上临时高亮光点
- 概率语义：散花是**演出+附加奖**，不改变主灯停位判定；主灯停在 LUCKY 格本身 → 按全清反赔（见下） 
- **主灯停在大 LUCKY**：×5 返还全部押注（无论押哪个符号）；停在小 LUCKY：×2 返还全部押注

## 4. 跑灯机制（v2，替代整轮旋转）

- **跑灯光圈**：一个金色发光描边框节点，逐格移动点亮
- **运动曲线**：起速快（每格 60ms）→ 线性 → 减速（每格逐渐拉长至 400ms）停在预抽格位；总时长 ~3.5s，总步数 = 2 整圈 + 停位偏移（起止格随机）
- **结果先抽后演**（不变）：先按权重抽停位，跑灯圈数保证 ≥2 圈增强悬念
- **经过触发格判定**：跑灯每步经过格 20（大L 左侧）/ 格 10（小L 右侧）→ 该步暂停 0.3s 播散花动画（散灯逐个弹入中央），然后继续跑
- 实现用**步进计时器**（SceneTreeTimer 逐格 await）而非 Tween（每格时长不同，Tween 不便）——这是 v2 与 v1 的实现架构差异

### 10.3 Lucky 散花（用户确认规则）
- 灯进入「大Lucky 左邻」或「小Lucky 右邻」格时触发散花预告（该格闪烁）
- 散花：从 Lucky 格飞出灯珠（大 Lucky 5~7 个 / 小 Lucky 3~4 个，数量预抽；可一次全出或逐个出，实现取逐个 80ms 间隔）
- 每颗灯珠沿环随机方向跑 4~8 格停在随机格（预抽），最终停格集合 = 散花结果
- **结算**：主停格 + 所有散花停格，每格独立判定「玩家押注 ∩ 停格符号」→ 倍数相乘，合计为总局得分（用户确认：所有压中格合计）
- 大 Lucky 散花停格含 Lucky 自身 → 特别奖 ×50；小 Lucky 散花含自身 → ×25（对齐 BAR 赔率梯度）
