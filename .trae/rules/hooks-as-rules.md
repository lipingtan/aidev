# 自动触发规则（源自 .kiro/hooks 转换）

> Trae 无原生 hooks 机制，以下规则作为 AI 行为约束内联到 rules 中生效。

## 规则1：始终使用中文回复

所有回复必须使用中文。

## 规则2：提示词一致性检查

当提示词文件（`src/**/prompts/**/*.md`）被编辑后，执行一致性检查：
1. 找到该文件所属项目目录
2. 读取该项目的 `story/characters.md` 和 `story/style-bible.md`
3. 检查编辑后的提示词中角色描述关键词、风格锚定词是否一致，是否包含负面提示词
4. 发现不一致时提醒用户并建议修正；一致则简短确认
5. 只检查一致性，不自动修改文件

## 规则3：分镜完成提醒

当新的分镜文件（`src/**/storyboard/ep-*.md`）被创建后，简短提醒用户：该分镜已就绪，可以生成对应的 KLING AI 提示词了。不要自动生成。

## 规则4：Task 全部完成后三角色验收

当 `tasks.md` 完成率达到 100%（含「完成率 | N/N (100%)」标记）时，立即执行三角色验收：

### 业务专家验收
- 需求覆盖度：requirements.md 中每个 FR-N 的验收标准是否都有代码实现
- 多租户隔离：新增表/接口的租户隔离规则是否正确
- 异常场景：所有降级/兜底/错误场景是否都有代码实现
- 权限边界：CRUD 权限是否正确限制到指定角色

### 产品经理验收
- 前后端字段对齐：打开前端 Vue 文件 + API 模块逐条核对后端 JSON tag
- 表单组件类型：下拉选择器必须是 el-select，不得是 el-input 手填 ID
- 菜单图标：后端 seed 中的 icon 名是否在前端全局注册范围内
- 空状态/加载态/错误提示：列表有 el-empty、操作有 loading、错误有 ElMessage
- 乐观锁 version：编辑表单隐藏携带 version，接口返回包含 version
- 分页参数：前后端 page/page_size 命名一致
- 雪花 ID 精度：int64 字段前后端均用 string 类型
- 删除确认：危险操作有二次确认弹窗，文案含操作对象标识

### 架构师验收
- go build ./... 零错误，go vet ./... 无警告
- 不变行为清单（RG-N）：每条回归项仍然成立
- 缓存一致性：写操作成功后才失效缓存
- 中间件顺序：公开路由不走 AuthMiddleware，admin 路由走完整链
- 乐观锁实现：Update 的 WHERE 含 version，RowsAffected=0 时返回冲突错误
- 软删除兼容：唯一性校验只查活跃记录（deleted_at IS NULL）
- Repository 分层：不在 Repository 层做跨表 JOIN

验收方式：逐条打开实际代码文件验证（不凭记忆），发现问题按高/中/低分级记录，全部通过后输出「✅ 三角色验收通过」。
