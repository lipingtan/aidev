# Palantir 模式落地实施手册

> 适用场景：toB 定制开发 + AI 应用公司，成长期，面临利润低、增长瓶颈、客户流失

---

## 问题诊断：你的三个痛点本质上是一个问题

利润低、增长瓶颈、客户流失，根因是同一个：**你在卖人力时间，而非卖不可替代的价值**。

定制开发的经典死亡螺旋：
```
接项目 → 堆人做 → 交付完客户走 → 再接新项目 → 价格战 → 利润更低
```

Palantir 的破局逻辑：
```
沉淀平台 → 定制只做上层 → 交付后客户离不开 → 扩展更多场景 → 利润递增
```

---

## 实施路径：分三步走，6个月见效

### 第一步：止血——从"项目制"转向"平台+定制"（月1-2）

#### 具体做什么

**1. 梳理过去项目，提取可复用模块**

立即盘点过去 12 个月交付的所有项目，按以下维度分类：

| 分类 | 示例 | 处理方式 |
|------|------|----------|
| 重复造的轮子 | 用户管理、权限、审批流、数据看板 | 抽象为内部平台模块 |
| AI 能力重复集成 | RAG 问答、文档解析、数据分析 Agent | 封装为可配置的 AI 中间件 |
| 纯客户定制逻辑 | 特定业务规则、UI 定制 | 保留为项目层，每次单独做 |

**2. 构建内部交付平台（你的"Foundry"）**

不需要很大，先做一个最小可用版本：

```
你的平台架构（最小版）：
├── 基础层：用户/权限/租户/审计日志（所有项目通用）
├── AI 能力层：RAG引擎/Agent框架/模型路由/Prompt管理（可配置）
├── 业务模板层：审批流/数据看板/报表引擎（按行业沉淀）
└── 定制层：客户特有逻辑（这才是每个项目真正要写的代码）
```

**目标**：下一个新项目，定制代码量降低 60%，交付周期缩短一半。

**3. 立即停止的事**

- 停止接"纯人力外包"性质的项目（利润 < 30% 的不接）
- 停止每个项目都从零搭建基础架构
- 停止让最强的工程师写 CRUD

---

### 第二步：建立粘性——从"交付即走"转向"持续运营"（月2-4）

#### 具体做什么

**1. 重新设计商业模式：项目费 + 年度服务费**

| 收费项 | 说明 | 参考定价 |
|--------|------|----------|
| 项目交付费 | 一次性，覆盖定制开发成本 | 降低 20-30%（让客户更容易启动） |
| 平台年费 | 基础平台模块使用权 + 维护升级 | 项目费的 15-25%/年 |
| AI 能力用量费 | 按 Token/调用次数/活跃用户计费 | 按实际使用收费 |
| 运营支持费 | 可选，含数据优化/模型调优/新场景扩展 | 按需报价 |

**关键话术转变**：
- 旧：「我们帮你做一个系统，做完交付」
- 新：「我们为你搭建一个AI运营平台，持续帮你的业务变得更智能」

**2. 植入"离不开"的设计（运营锁定）**

参考 Palantir 的本体论锁定，在你的交付中植入以下粘性设计：

| 粘性机制 | 具体做法 |
|----------|----------|
| 数据沉淀 | 客户业务数据持续积累在你的平台上，迁移成本高 |
| AI 模型进化 | 基于客户数据的微调模型/知识库，越用越准，无法带走 |
| 业务流程嵌入 | 让你的系统成为客户日常工作流的一部分，而非"偶尔用的工具" |
| 集成生态 | 与客户现有系统（ERP/CRM/OA）深度对接，拔掉你=业务中断 |

**3. 设立"客户成功"角色（你的 FDE）**

不需要像 Palantir 那样驻场，但需要：

- 每个重点客户指定一个技术对接人（不是销售，是懂业务的工程师）
- 每月主动做一次"AI 效果复盘"：模型准确率、使用频次、新场景机会
- 每季度提一个"扩展建议"：「你们xx部门的xx问题，也可以用AI解决」

**这就是"获取→扩张"的具体动作。**

---

### 第三步：增长——选定垂直行业深扎（月3-6）

#### 具体做什么

**1. 选择 1-2 个垂直行业，做到"最懂"**

选择标准：
- 过去客户中哪个行业最多（已有案例积累）
- 哪个行业数据复杂度高、AI 需求强（利润空间大）
- 哪个行业竞争对手尚未形成垄断

常见高价值垂直方向（AI 定制开发适用）：
- 制造业：质检AI、设备预测维护、供应链优化
- 金融：风控模型、智能客服、合规审查
- 医疗/医药：病历结构化、辅助诊断、药物研发数据
- 教育：自适应学习、AI 批改、知识图谱
- 法律：合同审查、案例检索、法规问答

**2. 构建行业知识壁垒（你的"本体论"）**

选定行业后，做这些事：

```
行业知识沉淀体系：
├── 行业数据模型：该行业核心实体、关系、业务规则的标准化定义
├── 行业 Prompt 库：经过验证的高质量提示词模板
├── 行业训练数据：脱敏后的标注数据/微调数据集
├── 行业最佳实践：踩过的坑、有效方案、性能基准
└── 行业案例库：可对外展示的成功案例（获取新客的武器）
```

**3. 改变获客方式：从被动接单到主动猎取**

| 旧模式 | 新模式 |
|--------|--------|
| 等客户发 RFP | 主动找目标行业企业，提供免费诊断/POC |
| 拼价格投标 | 用行业案例 + 平台demo 展示差异化价值 |
| 通用宣传 | 行业垂直内容营销（公众号/白皮书/行业会议） |

**POC（概念验证）策略**——参考 Palantir 的"AIP训练营"：

- 为目标客户提供 1-2 周的免费/低价 POC
- 用你的平台快速搭建一个小场景，让客户看到效果
- POC 成本可控（因为有平台支撑），转化率高
- 这就是 Palantir"获取阶段亏损换客户"的轻量版

## 关键指标追踪

| 指标 | 当前（预估） | 6个月目标 |
|------|-------------|-----------|
| 项目毛利率 | 15-25% | 40%+ |
| 新项目交付周期 | 3-6个月 | 1.5-3个月 |
| 客户续费/扩展率 | 接近 0 | 30%+ |
| 单客户年收入 | 一次性项目费 | 项目费 + 年费（LTV 翻 3 倍） |
| 定制代码占比 | 80%+ | 30-40% |
| 平台复用率 | 接近 0 | 60%+ |

---

## 立即可以开始的 5 件事（本周）

1. **列清单**：盘点过去所有项目中重复开发的模块，按复用价值排序
2. **选行业**：确定最有积累的 1 个垂直行业，All-in
3. **改合同模板**：下一个新客户开始，合同中加入"年度平台服务费"条款
4. **指定客户负责人**：给 Top 3 现有客户各指定一个技术对接人，本周做一次回访
5. **启动平台 MVP**：把复用价值最高的 3 个模块，开始抽象为独立可配置组件

---

## 总结：你的转型公式

```
从：项目公司（卖人天 × 低利润 × 做完就散）
到：平台公司（卖解决方案 × 持续收费 × 越用越深）
```

核心心法：**不是少做定制，而是让定制只发生在高价值层；底下的平台越厚，上面的定制越赚钱。**
